# AETERNA-v1

**Единый Rust/EvoPhase/U1 когнитивный runtime без LLM**, CPU-first.
Бинарник `aeterna-v1`; `aeterna-unified` — совместимое имя того же
исполняемого кода. Совместный владелец памяти и защиты — `ScientificRuntime`.

**Каноническая ветка после интеграции [PR #9](https://github.com/kelbas2007/Aeterna-v1/pull/9) — `main`.** Новый вход для документации:
[текущий статус, 20 октября 2026](docs/CURRENT_STATUS_20261020.md).

## Начало работы

Нужны Rust **1.99.0**, зависимости из `Cargo.lock`.

```bash
cargo run --locked -- --help
cargo run --locked -- --status
cargo run --locked -- --jsonl
cargo run --locked -- --inspect path/to/checkpoint.json
python scripts/check_project.py
python scripts/check_docs.py
```

`--status` сообщает о функциях, не об уже выученных знаниях.
`--inspect` только читает указанный checkpoint. В JSONL действия исполняет
**доверенный виртуальный мир**, а реальные последствия возвращаются через
POST. HumanProtection выдаёт новое разрешение для каждого шага.

**Ограничение интерфейса:** стандартный JSONL `init` фиксирует
`planning_depth=2`; эксперименты на 3–5 действиях использовали явную
Rust-конфигурацию `ScientificRuntime`. Одно включение opt-in через JSONL
не воспроизведёт опубликованные результаты. [Руководство JSONL](docs/JSONL_AUTONOMOUS_OPTIONS.md).

## Что объединено

EvoPhase/U1, фактический защищённый Learner, EP1, School/SG1, REL1,
RSP2, кандидатные RSP3 и LC1, исследовательские причинные пробы,
приобретённые последовательности действий, ограниченный выбор глубины
памяти и доказательная проверка необходимости усложнения. RSP2
сохраняет свои критерии принятия поисковых улучшений; кандидат не получает
автоматически право на внешние действия.
