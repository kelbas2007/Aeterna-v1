# Непрерывный сенсорный опыт и поиск способа обучения

Экспериментальное расширение единого `ScientificRuntime`. Наличие реализации
не доказывает развитый интеллект. Условия проверки способности зафиксированы
в [протоколе](CONTINUOUS_RULE_LEARNING_PROTOCOL.md).
[Итоговая проверка отрицательная](CONTINUOUS_RULE_LEARNING_RESULT.md):
поиск не изменил прогнозы и не дал принятого алгоритма или производителя.

## Что изменено

`LearningWorld` сохраняет последовательность исходных отсчётов и обучаемые
веса восьми временных лагов. Сигнал разворачивается в порядке измерений;
пиксель изображения или сцены имеет собственную временную историю. Пространственный
энкодер прежней сети продолжает работать. Общий прогноз объединяет сеть и
временную модель по их прошлым ошибкам. Физическая модальность определяет
структуру входа, имена файлов и классы не передаются.

Из признаков прогноза обучается поправка к предсказанной награде и ценности
действия. Эти оценки поступают прежнему U1. Подтверждённые ответы обучают
модели; внутренние расчёты не добавляют фактических событий. Если временная
модель устойчиво лучше реконструкции сети, коэффициент сети мал и награды
предсказываются достаточно точно, дорогая реконструкция приостанавливается.
Обучение наградам продолжается; изменение условий возвращает реконструкцию.

Поиск RSP2 меняет исполняемую программу обновления весов. Её входы — текущий
и предыдущий градиент, временной признак, остаток прогноза, вес и число прошлых
наблюдений. Исходная программа возвращает текущий градиент. Общие операции VM
и правила изменения синтаксиса написаны на Rust. Поиск составляет выражения
из этих операций; изобретение произвольных новых вычислительных примитивов
этой реализацией не заявляется.

Предложенная программа получает теневую копию действительных весов. Оба
ученика видят одинаковые последующие ответы. Программа допускается по ошибке
полного прогноза, после чего новые настоящие наблюдения обновляются уже ею.
Квитанции сохраняют код, момент предложения, ошибки и решение. Поиск также
может менять свою политику, используя тот же существующий движок RSP2.
Допуск политики требует пользы в прямой роли, в двух ролях производителя
следующих учеников и на сохранённом опыте. Исторический точный режим RSP2
остаётся в том же организме со своими прежними счётчиками.

## Один организм и ограниченная память

Все веса, последовательности, исходные состояния фрагментов, программы,
политики поиска, квитанции и генераторы случайных чисел входят в тот же
checkpoint. Единственный владелец фактического действия — прежний runtime.
Отдельного Python-агента, выбирающего программу или сообщающего ей успех, нет.
Python передаёт измерение и сохраняет нативный ответ.

Режим хранит не больше 2048 физических рядов с восьмью последними значениями,
частичными фрагментами до 48 значений и ограниченными весами. Поисковая память
ограничена 64 последними фрагментами, 16 старыми опорными фрагментами,
четырьмя контрпримерами, 64 аудитами и 32 квитанциями программ. Не принятые
из-за ёмкости значения отражаются в отчёте. Это ограниченная память опыта,
а не возможность вместить произвольный объём знаний без потерь.

Идентичный `PRE` соседнего окна HAR теперь продолжает предыдущий `POST`.
Новый эпизод объявляется при действительном разрыве последовательности.
Перезапуск очищает текущую историю и калибровку, но сохраняет приобретённые
веса, программу, поисковую политику и ограниченную память. Заморозка прекращает
изменение обучаемого состояния.

## Запуск

После `organism_init` либо загрузки checkpoint с `LearningWorld`:

```json
{"op":"organism_enable_temporal_learning","config":{"search":true,"recursive":true}}
{"op":"world_prediction","action":0}
{"op":"organism_report"}
```

При подключении к прежней жизни сначала передайте фактическое начальное
наблюдение через обычный перезапуск интерфейса. Подключение требует оставшегося
вычислительного бюджета. Оно не создаёт новое фактическое действие.
`world_prediction` возвращает общий прогноз, составляющие и коэффициенты,
`temporal_prediction` — диагностический прогноз временной модели.

Пример продолжения на записях:

```bash
python scripts/prepare_continuous_rule_stream.py \
  --manifest docs/evidence/continuous-rule-learning/data-sources.json \
  --data-root /path/to/pinned-nab-csv --split development \
  --output /tmp/development.jsonl
python scripts/learning_world_stream.py --binary target/release/aeterna-v1 \
  --checkpoint docs/evidence/learning-world/physics/one-organism.json.gz \
  --events /tmp/development.jsonl --output /tmp/temporal-life \
  --temporal --forecast-log --limit 7000
python scripts/replay_learning_world.py --binary target/release/aeterna-v1 \
  --results /tmp/temporal-life --output /tmp/temporal-replay
```

Файлы CSV размещаются под именами `<group>.csv` из манифеста, например
`realAWSCloudwatch.csv`. Препаратор проверяет SHA256 закреплённых исходников.
Оценочный суффикс генерируется с `--split evaluation` только после фиксации
исходников и бинарника; затем продолжается соответствующий checkpoint.
Драйвер записей предлагает только историческое действие продвижения записи.
Он не управляет исходным сервером, дорожным движением или экспериментом.

Проверки корректности: `cargo test --release --test temporal_organism` и
`python scripts/check_project.py --release`. Полное сравнение использует
`scripts/continuous_rule_analysis.py`, три простых прогноза и одинаковый
организм с фиксированным алгоритмом обновления. Результат должен отдельно
показать улучшение приобретения, стоимость и принятие рекурсивной политики.
