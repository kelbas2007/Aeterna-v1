# Многомерное восприятие: изображения и числовые признаки

Режим находится в `research/beyond-intel4`. Он приобретает ограниченные образцы
из фактических наблюдений и результатов выбранных действий. Числовые центры
и сила связи образец → действие хранятся только в общих фазовых связях EvoPhase.
Метрика расстояния, сжатие образцов, голосование соседей и стратегия исследования
заданы программно. Это обучаемый компонент восприятия, а не универсальный интеллект.

## Работа с файлом

После переключения на исследовательскую ветку:

```bash
cargo run --locked --release --bin perception -- train tests/data/digits.csv /tmp/digits-model.json
cargo run --locked --release --bin perception -- recognize /tmp/digits-model.json /path/to/digit.png
cargo run --locked --release --bin perception -- correct /tmp/digits-model.json /path/to/digit.png 7 /tmp/digits-corrected.json
```

`train` читает CSV во время запуска, исключает заранее фиксированные контрольные
строки и сохраняет новый checkpoint. `recognize` загружает его в отдельном процессе
и замораживает обучение. `correct` получает внешнюю аннотацию, позволяет организму
выбирать действия и приобретать фактическую обратную связь, затем пишет новый файл.
Существующий checkpoint не перезаписывается.

PNG, JPEG и PGM преобразуются в 8×8 градаций серого. Нужна вырезанная одиночная
цифра с тёмным фоном и светлыми штрихами; для светлого фона добавьте `--invert`
к `recognize` или `correct`. Используйте непрозрачные изображения. Максимальный
размер — 2048×2048 и 8 MiB файла. Изображение целой страницы, произвольная
ориентация или фотография сцены не входят в проверенный контракт.

Прогноз печатает `digit`, расстояние и `vote_margin`; последний является разностью
голосов, а не вероятностью правильного ответа. При недостаточной поддержке
печатается отказ. Прогноз имеет `authority=IMAGINED`; аннотация исправления
остаётся у внешнего приложения. Канонические checkpoint этой утилиты используют
действия 0–9 для цифр и действие 10 для измерения. Не используйте здесь checkpoint
экспериментов с переставленными действиями.

## Общий интерфейс

Создайте EvoPhase с нужным числом сенсорных и моторных ячеек и достаточным числом
спящих ячеек. Включите native planning, online learning, затем
`enable_phase_vector_learning(PhaseVectorConfig)`. Этот режим включается на
холодном организме отдельно от режимов круговых правил и других специализаций.

В `ScientificRuntime` задайте `set_outcome_goal(1.0)`, передайте фактический кадр
через `observe_external` или `observe_external_partial`, затем используйте
`step_unified` или `step_partial`. Внешний callback возвращает фактический POST
и результат выбранного действия в 0..=1. Метки класса, формулы и готовый правильный
мотор не передаются в EvoPhase. Цель считается достигнутой только по фактическому
результату callback. Старый `step`, который возвращает лишь кадр, в этом режиме
не принимает действие: для обучения необходим внешний результат.

Признаки лежат в 0..=1; отсутствующий признак обозначается `None`. Ноль и единица
кодируются разными фазами на половине окружности. При неизвестных признаках
выбирается единственное подтверждённое действие измерения. После получения кадра
выбирается поддержанный ответ. При замороженном обучении недостающая поддержка
приводит к отказу. Общий runtime сохраняет проверки свежего наблюдения, одноразовое
разрешение действия, остановку и аудит.

По умолчанию выделяется 32 образца на действие. Положительный фактический PRE
создаёт новый образец при достаточном отличии, пока есть слот; затем уточняет
ближайший центр. Ошибочный фактический ответ ослабляет его физическую моторную
связь. Прогноз использует три ближайших проводящих образца. Число слотов, связей
и сохранённых идентификаторов подтверждения ограничено. Полная история кадров
и исходные изображения в checkpoint не накапливаются. Возможны потеря редких
образцов и конфликт старой и новой обратной связи; всестороннее удержание знаний
после произвольных исправлений пока не проверено.

Поддерживается до 1024 признаков при совместном лимите 512 образцов и 65536
новых связей. Для цифр выделено 352 слота и 22880 связей; после обучения занято
320 образцов, checkpoint занимает около 2,5 MiB. Одновременная допустимость
ширины, числа действий и слотов проверяется перед включением.

Механизм принимает любые нормированные числовые признаки и может использоваться
для сигналов. Отдельная проверка на записанных временных сигналах ещё нужна.
[Новая индукция программ](INDUCED_PROGRAMS.md) добавляет к vector mode приобретённые
пороги и ветви. Её качество на изображениях и временных сигналах ещё не измерено.
Совместное применение этого режима с символическим выводом, текстовыми знаниями
и многошаговым планированием в одной модели ещё не реализовано.

## Сохранение и проверка

Writer v9 сохраняет фактически приобретённые параметры и читает старые v1–v8.
Свежий кадр, результат эпизода, цель, разрешение действия и текущие отказы
не сериализуются. Восстановление runtime требует нового наблюдения и сохраняет
живые настройки цели, заморозки и аварийной остановки. Повреждённый checkpoint
отклоняется атомарно.

```bash
cargo test --locked --release --test vector_learning --test real_digits --test perception_cli -- --nocapture
cargo run --locked --release --example real_digits
bash scripts/demo.sh
```

Восемь инженерных проверок охватывают фактическое исправление, границу
REAL/IMAGINED, измерение через защищённый runtime, физические cut/π/restore,
некорректные данные, ограниченную память, атомарное восстановление и неисправный
POST. Отдельная CLI-проверка запускает обучение и распознавание реальных PNG/JPEG
в разных процессах, проверяет инверсию, исправление, неизменность исходного файла
и отказ от перезаписи. [Результат цифр](DIGITS_BENCHMARK.md) сравнивает качество
с простыми алгоритмами по [фиксированному протоколу](VECTOR_PROTOCOL.md).

## Экспериментальный двигатель приобретённых программ

Добавьте `--programs` к `perception train`, чтобы обучить условные программы с
приобретёнными операциями и обучаемыми предпочтениями конструктора. `recognize`
и `correct` используют двигатель из checkpoint. Прототипного запасного ответа
нет. Первое сравнение этого режима дало 143/364 цифры, заметно хуже прежнего
прототипного режима; заданный порог качества FAIL. Подробности и реальные
сигналы: [приобретённые операции](ACQUIRED_OPERATIONS.md).
