## Что изменилось в исполняемом процессе

Старая ветка принятия требует отсутствия ухудшения на каждом прошлом примере
и заканчивает пробу после короткого `shadow_steps`. Она сохранена без изменения
для прежнего режима. В шумном процессе случайный удачный прогноз старой модели
может запрещать более полезное обобщение.

Новый явно включаемый режим фиксирует кандидата, исходную программу, библиотеку,
координату прогноза, границу истории и статистический порог **до первого нового
исхода**. Записанные программой PRE-прогнозы сравниваются с фактическим POST.
Незавершённая проверка продолжается после старого короткого окна. Ни вызов
планирования, ни просмотр состояния, ни восстановление checkpoint не добавляют
наблюдений и не создают новую статистическую попытку.

Одна проверка остаётся активной. Конкурентное слияние нескольких изменений не
введено. Кандидат по-прежнему получается обычным существующим синтезатором.
EP1 не подставляет в него готовую программу решения.

Файлы реализации:

- `src/construction/epistemic.rs`: фиксированная политика, последовательное
  свидетельство, учёт попыток, структурная область изменения.
- `src/construction/runtime.rs`: включение режима, настоящие PRE/POST,
  сохранение и восстановление, окончательное принятие либо отказ.
- `src/construction/recursive.rs`: независимое воспроизведение доказательства
  относительно замороженных программ и прежние сравнения конструкторов.
- `tests/directed_construction_epistemic*.rs`: сквозные и отрицательные проверки.
- `examples/directed_construction_epistemic.rs`: запускаемый контраст старого
  и нового рабочего runtime с замороженной последующей проверкой.

## Статистический контракт

Решение использует заранее определённую ограниченную потерю: точное совпадение
целочисленного значения выбранного выхода, то есть ошибку 0/1. Это не тест
улучшения абсолютной ошибки, NLL или безопасности действия. Они не должны
приписываться ему автоматически.

Для нового события `t`:

```
g_t = error_01(parent_t, actual_t) - error_01(candidate_t, actual_t)
E_t = mean_b product_{s<=t} (1 + b*g_s)
b in {0.0625, 0.125, 0.25, 0.5}
alpha(j,k) = total_alpha / width / (k*(k+1))
```

При нулевой гипотезе `E[g_t | PRE history] <= 0` каждый множитель неотрицателен,
а каждый процесс произведений имеет условное ожидание не выше предыдущего
значения. Среднее этих процессов сохраняет это свойство. Порог `1/alpha`
допускает последовательный просмотр. Сумма выделенных `alpha(j,k)` не превышает
фиксированного `total_alpha` за жизнь данного журнала. Это не вероятность того,
что конкретная принятая модель «правильна», и не гарантия качества после смены
распределения.

В коде используется сумма логарифмов и устойчивое вычисление среднего.
Попытка не получает риск обратно после отмены или отката. Кандидат, библиотека,
целевой индекс и граница истории связаны с одним билетом проверки.

## Сохранность и полномочия

EP1 разрешает изменить только выбранный выход. Остальные выражения сохраняются
буквально; существующие ячейки состояния и их правила обновления также не
меняются. Можно дописать новые ячейки. `protected_outputs` полностью запрещает
статистическое изменение указанных существующих выходов. Политика задаётся
один раз до опыта; детерминированный контракт нельзя переключить этим API.

Это консервативная защита уже существующих вычислений. Она не доказывает
сохранение всех редких контекстов внутри изменяемого стохастического выхода.
Такие обязательства нужно объявлять отдельно; EP1 не заменяет их средней
точностью.

Свидетельство, долг риска и пробная модель сериализуются в общем когнитивном
checkpoint. При чтении проверяются билет, граница, реальные записи и повторное
исполнение замороженных программ. Семь дополнительных тестов включают
взаимно согласованную подделку прогнозов и статистики с пересчитанной контрольной
суммой: она всё равно отвергается проверкой исполняемой программы.

Контрольная сумма checkpoint не является криптографической подписью. Хост и
поставщик фактических наблюдений остаются границей доверия. Этот механизм не
является защитой от произвольной замены всего процесса привилегированным хостом.

`restore_cognition` сохраняет прежний контракт: нельзя вернуть живой адаптер к
старой истории, стереть стоимость действия или снять защёлкнутую защиту.
Проверены сериализация и новые экземпляры `Learner::from_checkpoint`, а также
160 восстановлений живого адаптера внутри процесса. Это не отдельная
квалификация нового межпроцессного адаптера внешних полномочий.

Разрешение физических действий остаётся у EvoPhase. Новая статистика не
выдаёт разрешений. Отказ или ошибка последнего аудита не могут быть заменены
положительной предварительной оценкой. Свидетельство улучшения прогноза не
считается автоматически свидетельством ускорения поиска: сравнения с той же
библиотекой и с предком конструктора сохранены.

Объём ограничен существующим журналом, максимумом наблюдений пробы и числом
доступных билетов. Исчерпание бюджета означает отсутствие решения, а не право
удалить историю, переиспользовать наблюдения или снять защиту.

## Воспроизводимый рабочий пример

```
cargo run --locked --example directed_construction_epistemic
cargo test --locked --lib construction::
cargo test --locked --test directed_construction_epistemic
cargo test --locked --test directed_construction_epistemic_integrity
```

В авторском обучающем потоке 256 событий: четыре единицы на пять наблюдений,
первое наблюдение — ноль. Используется существующий поиск одноузловых программ.
Внешнее действие задано стендом и проходит прежний защитный интерфейс.

Старая модель не получила ни одного принятого изменения. EP1 самостоятельно
выбрал и принял константный прогноз 1 после **85 новых событий проверки**
(граница обучения — событие 32, `alpha=0.005`, `log(E)=5.560565402928542`).
Первый ноль и остальные фактические записи сохранились.

После обучения обе программы заморожены. На 1000 одинаковых последующих
псевдослучайных наблюдениях старый режим сделал **317 ошибок**, EP1 — **204**.
Ни один из этих исходов не использовался для дообучения, изменения порога или
выбора новой программы. Это один разработческий контраст, а не независимая
оценка общего интеллекта. Новых конструкторов в этом простом EP1-примере: **0**.

Режим подключается вызовом `enable_epistemic(EvidencePolicy)` до первого опыта.
Пример содержит полную настройку. Старые режимы и примеры не переключаются
молча; иначе изменился бы смысл их детерминированных контрактов.

## Инфраструктура и свидетельства

`.github/workflows/ep1-runtime.yml` устанавливает закреплённый toolchain,
компилирует все цели, запускает выбранные регрессии и три примера, сохраняет
результаты. Первая интеграция была опубликована автоматически **только после**
успеха проверок. Временный установочный workflow и staging-код удалены из
финального дерева; постоянный проверяющий workflow имеет только `contents: read`.

Сборочный `target` в Git не добавлялся. Малые журналы хранятся 7 дней,
временный архив исходников — 1 день; постоянные исходники остаются в коммитах.
Машиночитаемая сводка: `docs/evidence/EP1_RUNTIME_INTEGRATION.json`.

Статус: реализованный и проверенный механизм EP1 в исследовательском runtime.
Это программный механизм, не новое доказательство владения вычислением со
стороны SNN, не человеческий язык и не подтверждение AGI.
