## Question

Can one `ScientificRuntime`, with a single opt-in temporal-evidence project, automatically (i) reset only transient evidence on real externally marked episode start, (ii) accumulate only genuine raw observed POST, (iii) reinforce a sensory affordance only after actual cue-to-different-cue consequences, and (iv) offer the physically supported sensing action through the SAME U1 competition, without invoking a host mode switch/priority?

## Strict runtime ownership

- `ScientificRuntime::enable_temporal_evidence(config)` accepts only resource/evidence thresholds. No hidden side, action identity, noise reliability, world ID, correct answer, mode flag or experimental target.
- `observe_external` is the generic external episode boundary and samples the first raw observation. Nothing from the hidden simulator is encoded.
- `step_unified`: only after the protected motor has been permitted, executed and a valid real POST returned may EvoPhase update the factual sensory-motor link and, if that POST belongs to the already-acquired two cue sources, physical evidence memory.
- A new third class/terminal observation is **never automatically registered as a second cue** during action POST; only an external actual episode-start frame may recruit cue identities.
- While learning is frozen, no new physical sensory-motor affordance is recruited; already-acquired cue evidence can be accumulated transiently.
- The sensory action only becomes an ordinary U1 proposal if a physically conducting motor→hub link exists and physical readout needs more. No host direct action override; Human Protection remains final.
- If the temporal module is not enabled, all previous INTEL-4 action selection, learned fingerprint, checkpoint, CI and safety behavior remain unchanged.
