# Индукция программ из опыта

Новый экспериментальный путь на `research/beyond-intel4` строит программы
условных переходов из фактических числовых входов и результатов выбранных действий.
Он не использует меню `Atom/And/Xor` из G23 и шаблоны круговых формул.
Исторический G23 и квалифицированный INTEL-4 сохранены для воспроизводимости.

| Что определяется | Источник |
|---|---|
| Доступные входы и моторы | Внешний интерфейс, непрозрачные индексы |
| Какой вход проверять, порог, ветви, глубина программы | Фактические различия и ограниченный поиск |
| Ожидаемый результат в листе и область поддержки | Фактические исходы и диапазоны наблюдавшихся входов |
| Условный переход, лист, стратегия поиска и бюджет | Общий алгоритм на Rust |

Конкретный оператор `XOR` в коде нового механизма отсутствует. Такая зависимость
может возникнуть как приобретённая последовательность ветвлений. Общий
конструктор кандидатов всё ещё написан на Rust: это индуктивное предположение,
а не способность самостоятельно изобретать любые вычислительные примитивы.
Полное фазовое владение алгоритмом обучения не квалифицировано.

## Цикл обучения

1. `ScientificRuntime` получает реальный кадр, выбирает мотор и исполняет его
   через существующее одноразовое разрешение. Callback возвращает POST и исход.
2. Полный фактический PRE и результат попадают в ограниченный буфер своего мотора.
3. Если программа отсутствует, не поддерживает кадр или ошибается, конструктор
   пробует границы между наблюдавшимися значениями. Он оценивает результат
   нескольких последующих ветвлений, включая варианты без немедленной выгоды.
4. Выбранная структура устанавливается в общих физических связях. Вход — это
   источник тестовой связи, порог — её фазовый сдвиг, ветви — адресаты двух связей,
   оценка результата — вес связи лист → мотор. Отдельного числового экземпляра
   программы для запасного чтения нет.
5. Кандидат проверяется на последующих фактических действиях. Данные, породившие
   его, не подтверждают его задним числом. Нужны восемь проверок программы и
   две проверки используемого листа; грубо неоднозначная оценка не подтверждается
   только за правильный знак.
6. При достаточной поддержке программа выбирает действие. Прогноз остаётся
   `IMAGINED`; достижение цели требует фактического результата.

После первого фактического противоречия программа немедленно теряет допуск,
даже если для замены ещё мало данных. При достаточных фактах программа того же мотора пересобирается в том же физическом
пуле, её поколение меняется, последующие проверки начинаются заново. Число
узлов и связей остаётся фиксированным. Буфер удерживает оба типа исходов; новая
фактическая обратная связь для идентичного входа вытесняет старые противоположные
исходы, сохраняя счётчик конфликтов. Это политика для детерминированных задач;
случайный шум и долговременное удержание всех навыков таким способом не решены.

Область поддержки листа хранится в физических связях как минимумы/максимумы
каждого признака. К запросам применяется фиксированный допуск 0,15. За пределами
поддержки, при неизвестных признаках или неоднозначных ответах система отказывается
от ответа. Проверенный пример OR/XOR с недостающей логической строкой даёт отказ.
Это не общий детектор всех возможных неоднозначностей: из произвольных данных
нельзя однозначно восстановить любую никогда не наблюдавшуюся строку функции.

## API и запуск

Создайте холодный EvoPhase, включите native planning, online и vector learning,
затем `enable_phase_induction(PhaseInductionConfig::default())`. Выделите
дополнительные спящие ячейки: по умолчанию 15 на мотор. Нормированные признаки
принимаются в 0..=1, пропуски — как `None`; поддерживается до 64 признаков при
совместных ограничениях памяти. Настройки проверяются до изменения организма.

Используйте `set_outcome_goal(1.0)`, `observe_external[_partial]` и
`step_unified`/`step_partial`. Семантику действий и правильные результаты хранит
внешняя среда. `phase_induction_predict` возвращает только воображаемый прогноз;
`phase_induction_programs` показывает физически сохранённую структуру и основания.
Когда индукция включена, действие выбирается её программой; прототипный прогноз
не используется как запасной ответ и прототипы не обучаются.

```bash
cargo run --locked --release --example induced_programs -- learn /tmp/aeterna-program.json
cargo run --locked --release --example induced_programs -- run /tmp/aeterna-program.json
cargo test --locked --release --test induced_programs --test induction_mechanism -- --nocapture
```

`learn` приобретает программу трёхвходовой чётности по выбранным действиям, пишет
новый файл и показывает приобретённые входы/пороги/ветви. `run` восстанавливает
его в другом процессе, замораживает обучение и проверяет новые числовые значения.
Checkpoint v8 читает v1–v7. Текущий кадр, цель и разрешение действия не сохраняются.
Восстановление требует свежего наблюдения и сохраняет живую заморозку и остановку.

## Открытая проверка

[Исходные отчёты](INDUCTION_RESULTS.txt) сохраняют оба результата.
[Протокол](INDUCTION_PROTOCOL.md) зафиксирован до первой оценки. Первоначальный
жадный вариант решил **512/512** задач двухвходовых функций, но первая
трёхвходовая чётность дала **16/32**, остальные трёхвходовые варианты тогда
не проверялись. Изменения после этого результата перечислены в протоколе.

После исправления общего поиска и подтверждения прогноза:

| Набор | Приобретённые программы | Образцы | Линейные центры |
|---|---:|---:|---:|
| Все 16 функций двух входов, две перестановки | 512/512 | 512/512 | 487/512 |
| Чётность, большинство, селектор трёх входов, две перестановки | 192/192 | 192/192 | 154/192 |
| Всего | **704/704** | **704/704** | **641/704** |

Все модели получили те же фактические обучающие взаимодействия. Каждый метод
использовал 1408 действий на 704 задачи; агент всегда сначала измерял вход.
Приобретение потребовало 15988 действий в 38 отдельных жизнях. Активно от 3
до 31 узла суммарно на три мотора; выделено 45 узлов, checkpoint 82672–98965 байт.
Нет заявленного преимущества над методом образцов.

Обучение посещает все логические строки. Проверка переносит программу на новые
числовые значения и сочетания отвлекающих входов; это **не** доказательство
восстановления неизвестных строк произвольной таблицы истинности. Наборы открыты
и синтетические, а алгоритм был доработан после первого неуспеха. Результат
является инженерной проверкой, не независимой научной квалификацией.

Девять проверок механизма подтверждают отсутствие готового кандидата до фактов,
последующее подтверждение, приобретённый порог 0,25 на данных полностью ниже 0,5, физические cut/изменение порога/restore, работу через
общий runtime, неподдержанное сочетание, пересмотр XOR → противоположный закон
за 768 эпизодов при фиксированной памяти, атомарное отклонение циклического
checkpoint и границы ресурсов. Первоначальная проверка сдвига порога выбрала
кадр, который не пересекал изменённую границу; её исправили, сохранив требование
физического изменения ответа.

[Реальные изображения](DIGITS_BENCHMARK.md) повторно дали 343/364 в прежнем
прототипном режиме. Качество новой индукции программ на изображениях, временных
сигналах и открытых задачах ещё не измерено. Текстовое понимание и универсальный
интеллект из этого результата не следуют.
