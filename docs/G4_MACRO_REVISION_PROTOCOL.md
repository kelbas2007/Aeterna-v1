# G4 — REVISION OF THE SAME ACQUIRED EVOPHASE MACRO

Status: **PRE-REGISTERED BEFORE G4 IMPLEMENTATION**

Date: 2026-10-06

## Question

When a previously successful acquired macro becomes partly wrong because the external world changes, can factual counterexamples revise the **same EvoPhase-owned macro identity** instead of deleting it, spawning a replacement macro, or hiding the contradiction?

G4 tests revision, not fresh program formation.

## Starting point

G4 starts from the qualified G3 organism:
- one acquired two-step branching macro;
- opaque first motor acquired from successful factual trajectories;
- two relational intermediate branches;
- each branch selects a different opaque terminal motor;
- transfer already demonstrated across unseen spatial bindings.

## World change

Only one branch law changes after G3 tuition.

Before change:
- relational intermediate A -> terminal motor 2 -> Need=true;
- relational intermediate B -> terminal motor 0 -> Need=true.

After change:
- intermediate A keeps the same raw relational appearance;
- old motor 2 now produces factual Need=false;
- a different opaque terminal motor produces Need=true;
- intermediate B remains unchanged.

The evaluator knows this change only to generate factual Need. It does not pass the new correct motor to cognition.

## Revision curriculum

Both REVISION and NO_REVISION arms begin as clones of the same qualified G3 state.

For the changed intermediate A, both arms receive the exact same fixed generic terminal-action exploration:
- every opaque terminal motor is tried;
- all factual Need outcomes are delivered;
- absolute raster translations differ from original G3 tuition.

REVISION:
- factual contradiction may alter evidence inside the already acquired macro.

NO_REVISION:
- receives and preserves the same factual episode sequence;
- macro revision is disabled.

No new macro formation is allowed during G4 revision.

## Required same-identity behavior

The pre-change macro ID is frozen before revision.

PASS requires:
- macro count remains 1;
- macro ID after revision equals the pre-change ID;
- the contradictory old branch/action evidence remains stored;
- revision counter on the same macro increases;
- old action becomes disfavored for intermediate A;
- newly supported action becomes selected for A;
- unchanged intermediate B keeps its old terminal action.

## Held-out evaluation

Learning is frozen after revision.

Two held-out absolute translations, absent from G3 tuition and G4 revision, are evaluated:
- changed context A must use the revised terminal action;
- unchanged context B must preserve the old action.

REVISION and NO_REVISION receive identical raw held-out inputs.

## Acceptance

G4 PASS requires all:

1. Both arms begin from an identical single acquired G3 macro.
2. Revision factual ledgers are identical across arms.
3. The same macro ID exists before and after revision; macro count stays 1.
4. At least one factual counterexample against the old A branch is retained in the macro state.
5. The same macro's revision counter increases.
6. Old A action remains represented as contradicted evidence rather than being silently deleted.
7. A newly factually supported A action becomes the selected branch action.
8. Unchanged B branch action remains correct.
9. On held-out translations, REVISION reaches factual Need in 2/2 contexts.
10. NO_REVISION fails the changed A context under the same two-action budget.
11. G0-G3 regressions remain PASS.
12. Rust tests and release build PASS.
13. Revision physical interaction cost is reported.

## Failure conditions

FAIL if:
- the old macro is deleted and a new macro gets a new ID;
- evaluator supplies the new correct terminal action;
- contradiction is discarded;
- revision fixes A by breaking unchanged B;
- revision arm receives different factual evidence than control;
- new macro formation is used as a substitute for repair.

## Next gate after PASS

G5 — hierarchical reuse: an acquired macro must become a child building block of a newly acquired higher-level macro, and that hierarchy must reduce physical/search cost on held-out tasks.
