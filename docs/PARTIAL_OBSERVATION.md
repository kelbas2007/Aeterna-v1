# Неполные наблюдения и действия для получения информации

Это opt-in расширение [режима приобретённых правил](LEARNED_RULES.md).
Организм применяет ранее приобретённые преобразования, даже когда часть
каналов скрыта, и выбирает действия, раскрывающие неопределённое значение.
Замороженная модель может получать сведения о текущем состоянии без изменения
знаний. Это development-реализация для детерминированных круговых каналов,
а не новый квалифицированный результат INTEL и не общий интеллект.

Также поддерживается [расширенный язык правил](EXPANDED_RULES.md).
Для суммы/разности требуются оба входных значения; если одно скрыто,
вывод остаётся неизвестным. Константа не требует известных входов,
но её ожидаемый результат всё равно не является текущим фактическим успехом.

## Запуск в двух процессах

```bash
cargo run --locked --release --example partial_observation -- learn /tmp/aeterna-partial.json
cargo run --locked --release --example partial_observation -- run /tmp/aeterna-partial.json
```

В облачной среде при необходимости сначала выполните
`source /workspace/.aeterna-env/activate.sh`. `learn` создаёт новый файл и
отказывается перезаписывать существующий. Сначала модель самостоятельно
выбирает действия и приобретает численные правила из полных фактических
наблюдений. Затем по неполным результатам действий приобретает сведения
о том, какие каналы видимы. Роли действий и маски оценщика ей не передаются.

При проверке второй канал скрыт. Одно действие переносит его значение в
видимый канал; после настоящего измерения модель перепланирует и достигает
цели ещё за два действия. `run` загружает тот же файл в отдельном процессе,
отключает обучение и повторяет задачу. Код внешнего мира находится только
в [примере](https://github.com/kelbas2007/Aeterna-v1/blob/research/beyond-intel4/examples/partial_observation.rs); планировщик его не вызывает.

Локальный запуск действительно выполнен в двух отдельных процессах:

```text
mode=learn acquired_rules=3 acquired_masks=3 rule_acquisition_actions=9 mask_acquisition_actions=9 information_actions=1 goal_actions=3 factual_goal=true stored_states=0 frozen_unchanged=true
mode=run acquired_rules=3 acquired_masks=3 rule_acquisition_actions=0 mask_acquisition_actions=0 information_actions=1 goal_actions=3 factual_goal=true stored_states=0 frozen_unchanged=true
```

## Контракт API

1. Включите native online и rule режимы, затем
   `enable_phase_partial_observation(PhasePartialConfig::default())`.
2. Создайте `ScientificRuntime`, передайте свежий кадр через
   `observe_external_partial(&[Some(0.0), None])`.
3. Задайте цель через `set_partial_goal(&[Some(target), None])`.
4. Используйте `step_partial` с внешними оценкой разрешения и исполнением.
   Исполнитель возвращает `(Vec<Option<f32>>, bounded_outcome)`.
5. Для проверки без обучения вызовите `set_model_learning_enabled(false)`.

`Some(0.0)` — настоящий ноль; `None` в наблюдении — отсутствие значения.
Все известные значения должны быть конечными и лежать в `[0,1)`.
Полностью пустой кадр допустим. В цели `None` означает отсутствие требования;
хотя бы один канал должен иметь требование. Полные `observe_external`,
`set_goal`, `step` и `step_unified` тоже работают, преобразуя значения в `Some`.
Вызов `observe_external_partial` начинает новый эпизод и сбрасывает текущие
гипотезы. Для сохранения последовательности используйте фактические POST
в `step_partial`, не начинайте новый эпизод после каждого действия.

`phase_partial_belief()` показывает последний фактический кадр отдельно
от вычисленных гипотез. Частичный кадр не материализуется в обычный
`current_real()` с выдуманными значениями. Прогнозы всегда имеют
`Authority::Imagined`. Достижение цели проверяется только по последнему
фактическому кадру: каждый требуемый канал должен быть действительно видимым
и совпадать с целью в допуске. Даже однозначно вычисленное скрытое значение
не подтверждает успех.

## Вывод и выбор действия

Для каждого выхода рассматриваются совместимые кандидаты приобретённого
правила. Значения читаются через физические фазовые связи; отдельной копии
сдвига нет. Если источник скрыт, результат остаётся неизвестным. Несколько
вариантов сохраняются как символические гипотезы; неизвестный элемент
означает любое значение круга, а не численную оценку или вероятность.

По умолчанию допустимы 32 гипотезы, максимум 128. При превышении ёмкости
варианты объединяются в более широкое множество: различающиеся значения
заменяются неизвестными. Они не отбрасываются ради ложной уверенности.
Декартово объединение выходов может добавлять невозможные корреляции и
приводить к отказу от доступного решения, но не сужает множество до одного
удобного ответа. Фактический POST исключает несовместимые гипотезы.

Видимость каналов приобретается по маскам фактических POST. По умолчанию
нужны три последовательных совпадения маски для каждого действия; изменение
маски начинает подтверждение заново. Поддержка хранит ограниченный набор
идентификаторов исполненных событий. Этот порог является инженерным
допущением для постоянной видимости при данном действии, а не доказательством
неизменности сенсора в произвольной среде.

Сначала ограниченный программный beam search ищет последовательность,
которая приводит к цели во всех сохранённых вариантах и заканчивается
действием с подтверждённой видимостью нужных каналов. Без такого плана
выбирается подтверждённое действие, делающее неопределённый выход видимым.
После фактического измерения выбор повторяется. Счётчик информации — число
неопределённых ожидаемых видимых каналов, а не энтропия в битах.
Оценка информации рассматривает ближайший POST, а не дерево всех возможных
будущих измерений.
При включённом обучении разрешены эксперименты для неизвестных правил и масок.
Без поддержанного плана или информативного действия замороженный runtime
возвращает `NoSupportedAction`.

Это программный вывод поверх приобретённых фазовых параметров. Он не
квалифицирует полное EvoPhase cognitive ownership, не учит сам принцип
выбора экспериментов и не строит оптимальную политику для произвольного POMDP.

## Обучение, противоречия и сохранение

Численные правила обновляются только при полностью фактических PRE и POST.
Вычисление недостающего значения никогда не превращает его в tuition.
Частично видимое противоречие при включённом обучении приостанавливает правило
и увеличивает его revision. Новая полная фактическая поддержка может подтвердить
его заново. Прочие действия сохраняют свои правила.

При выключенном обучении противоречия правил и видимости блокируют применение
соответствующей модели в текущем эпизоде. Learned fingerprint остаётся
неизменным. Эпизодические запреты и гипотезы сбрасываются свежим наблюдением
или перезапуском; они не являются постоянной памятью изменения закона.
Для сохранения пересмотренного закона нужно включить фактическое обучение.

Checkpoint v6 сохраняет правила, фазовые параметры, приобретённые маски
и их поддержку. Текущий кадр, гипотезы, цель и разрешение на действие в файл
не входят. Читаются также v1–v5. Декодер проверяет размеры, ограничения,
счётчики и уникальность идентификаторов источников; проверка не удостоверяет
автора файла. После загрузки требуется свежий кадр. Живой emergency stop
и режим freeze переживают восстановление.

При смене полного и частичного режима через `restore_online_checkpoint`
полная цель переводится без потери ограничений. Частичная цель с `None`
не имеет точного эквивалента в полном режиме: такая смена отклоняется
атомарно с `InvalidCheckpoint`.

## Проверки и границы результата

[tests/partial_observation.rs](https://github.com/kelbas2007/Aeterna-v1/blob/research/beyond-intel4/tests/partial_observation.rs) содержит
11 development-тестов:

| Проверка | Результат |
| --- | --- |
| 32 мира, 2–4 канала, перестановки трёх непрозрачных действий, новые начальные состояния после загрузки | 192/192 целей при freeze; 363 информативных действия; learned fingerprint неизменен |
| Обнуление приобретённой связи действия, раскрывающего скрытое значение, и точное восстановление | Без связи нет поддержанного действия; восстановление возвращает достижение цели за три действия |
| Настоящий ноль и вычисленный скрытый ноль | Видимый ноль учитывается; скрытый прогноз не объявляет успех |
| Несколько кандидатов и ёмкость одной гипотезы | Альтернативы сохраняются либо расширяются до неизвестного; скрытые значения не обучают правило |
| Изменение закона и повторное полное обучение | Правило отзывается и подтверждается заново; другое правило сохраняется |
| Противоречие закону и изменение видимости при freeze | Соответствующая модель блокируется в эпизоде; знания не переписываются |
| Разные действия открывают первый канал, второй канал либо ни одного | Маски приобретаются из POST; после загрузки выбирается измерение требуемого скрытого канала |
| Повреждение файла, исключение гипотез, старый v2 и смена режима | Повреждение отклоняется атомарно; старые правила читаются; ограничения цели сохраняются |
| Блокировка, некорректный POST, перезапуск с emergency stop | Исполнитель не вызывается при запрете; непригодный результат не учит; stop остаётся действующим |

192 задачи — шесть целей для каждой из 32 моделей, а не 192 независимых
обучения. Мировые семейства, бюджеты и проверки открыты и созданы вместе
с реализацией. Здесь проверен перенос ранее приобретённых правил на новые
частичные состояния; приобретение произвольного скрытого закона с нуля
не показано. Численные правила приобретаются при полном наблюдении, маски —
при частичном. Конкурентное преимущество и независимая научная квалификация
не заявлены. TE4 и его `DEVELOPMENT_FAIL` остаются без изменений.

На этапе введения неполных наблюдений `bash scripts/check.sh` завершилась с 101
успешным test invocation, 0 failed, 8 ignored и 79 filtered в 26 запусках
тестовых бинарников. Эти счётчики включают повторяющиеся общие fixtures
и не являются числом независимых экспериментов. Release-примеры всех трёх
режимов прошли сохранение и загрузку в отдельных процессах. Development CI
включает новый набор и новый пример; удалённый workflow пока не запускался.
`cargo check --locked --all-targets` и Clippy correctness для библиотеки
также прошли. Форматирование новых Rust-модулей, тестов и примеров проверено;
прежние предупреждения о стиле и неиспользуемом коде сохраняются.

Механизм ограничен детерминированными преобразованиями круговых каналов
с постоянной маской для каждого действия. Шум, вероятностные переходы,
условные правила, неизвестная размерность и произвольные программы не
поддерживаются. Поиск имеет явные бюджеты и может пропустить существующий
путь; при расширении неопределённости возможны дополнительные отказы.
Общий интеллект этим расширением не создан.

Последующее [расширение обратного вывода](INVERSE_INFERENCE.md) восстанавливает
скрытые операнды точных правил по фактическому POST. [Условные модели и шум](ADAPTIVE_RULES.md)
поддержаны в отдельном режиме полных наблюдений; приведённое выше ограничение
относится к исходному механизму частичных наблюдений.
