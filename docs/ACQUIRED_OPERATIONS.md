# Приобретённые операции и реальные данные

В экспериментальном режиме EvoPhase сохраняет подтверждённые условные программы
как составные вычислительные операции. Следующий конструктор может использовать
их выходы наряду с сырыми сенсорами. Пустой организм не содержит XOR, AND или
таблицы именованных функций. Определение новой операции возникает из фактических
различий, хранится в общем графе связей и исполняется чтением этого графа.

Это продолжение [индукции программ](INDUCED_PROGRAMS.md), а не замена исторического
G23 или квалифицированного INTEL-4.

## Что теперь приобретается

| Элемент | Источник и хранение |
|---|---|
| Определение составной операции | Фактически приобретённые тесты, пороги, переходы и значения листьев; физические связи |
| Возможность вызвать её в новой программе | Источник тестовой связи — выходная ячейка приобретённой операции |
| Предпочтение входов при равной ошибке кандидатов | Веса связей конструктора, изменяемые по последующим фактическим исходам |
| Основания и границы применимости | Происхождение из поколения проверенной программы, поддержка и физические диапазоны листьев |
| Исполнитель, ветвление, генерация порогов, ошибка и ограниченный поиск | Унаследованный общий алгоритм на Rust |

Самостоятельно приобретаются **составные операции**. Базовый исполнитель и
алгоритм поиска не возникли из опыта. Обучение предпочтений меняет лишь выбор
при равной ошибке; оно не приобретает весь конструктор и не изобретает любые
машинные инструкции. Полное фазовое владение обучением пока не квалифицировано.
Переписать поиск на другой язык не устранило бы эту границу.

## Как операция становится доступной

Программа должна быть неконстантной, выдержать требуемые последующие фактические
проверки целиком и в каждом листе и различать высокий/низкий исход. В свободный
пул копируются физические параметры и структура, а не ссылка на Rust-функцию.
Повторное идентичное определение не занимает новый слот. Определения могут
вызывать только ранее опубликованные операции: циклический граф запрещён. В одном запросе результат каждой операции читается
не более одного раза; временный кэш не сохраняется и не переживает запрос.

Старая операция сохраняется как числовое преобразование после изменения задачи.
Её прежнее соответствие мотору не считается действующим правилом нового мира.
Новая программа действия требует собственных последующих проверок. Прогнозы
остаются `IMAGINED`, фактическую цель устанавливает только внешний исход.

Конструктор допускает производный вход только когда приобретённая операция
поддерживает все факты текущей подгонки. При чтении неподдержанная операция
возвращает отсутствие прогноза; прототипного запасного ответа нет. Эта строгая
граница ограничивает перенос на разнообразные непрерывные данные.

По умолчанию библиотека содержит восемь заранее выделенных пустых пулов;
в реальном сравнении — четыре. После заполнения новые определения не добавляются:
обучаемое вытеснение и расширение библиотеки пока не реализованы. Суммарно не более
512 узлов программ/операций и 65536 связей; фактические буферы ограничены.
Это ограниченное хранилище, а не решение универсальной долговременной памяти.

## Проверки механизма

Инженерный сценарий приобретает двухвходовую зависимость, затем переходит к
трёхвходовой. Новые программы используют физический выход прежней операции;
восемь запросов с новыми числовыми значениями дают правильные действия.
Удаление связей библиотеки меняет ответы, точное восстановление возвращает их.
Эти проверки синтетические: так отдельно проверяется причинная роль механизма.

Другой контроль даёт два одинаково информативных входа. Последующие фактические
исходы приобретают предпочтение; вмешательство в его физическую связь меняет
выбор входа при пересборке. Запросы не изменяют библиотеку, предпочтения или
подтверждения. Проверены фиксированная память, границы холодного выделения,
сохранение, атомарный отказ от некорректного checkpoint и запрет самовызова.

## Реальная проверка того же двигателя

[Протокол](PRIMITIVE_PROTOCOL.md) задаёт настройки и пороги до первой оценки.
[Исходные отчёты](REAL_PROGRAM_RESULTS.txt) сохраняют результаты без изменения
критериев после оценки.

| Записанные данные | Программы с библиотекой | Ближайший образец, те же факты | Линейные центры | Отказы / ошибочные ответы | Заранее заданный порог |
|---|---:|---:|---:|---:|---|
| Рукописные цифры, 364 контрольных изображения | **143/364 — 39,29%** | 344/364 | 328/364 | 141 / 80 | ≥60%: **FAIL** |
| GunPoint, 150 контрольных сигналов движения | **104/150 — 69,33%** | 137/150 | 113/150 | 12 / 34 | ≥70%: **FAIL** |

Цифры: 1433 обучающих изображения, один проход, 6503 фактических действия;
587 тестовых действий, измерение первым во всех 364 случаях. Четыре приобретённые
операции, четыре использования при построении, 4896 фактических обновлений
предпочтений, checkpoint 3926691 байт.

Сигналы: исходный split 50/150, четыре прохода только по обучающим записям,
329 обучающих и 288 тестовых действий. Измерение первым во всех 150 случаях.
Две приобретённые операции, пять использований при построении, 234 фактических
обновления предпочтений, checkpoint 1450803 байт. Последовательные тройки
отсчётов усредняются до 50 признаков; нормализация подгоняется только на обучении.

Все модели видят те же фактические выбранные действия и внешние исходы. Метки
остаются у среды. Контроли приобретают мотор измерения из тех же фактов и выполняют измерение
и ответ за два действия: 728 действий на цифрах, 300 на сигналах. Первоначальный
адаптер предполагал роль измерения; после исправления все числовые результаты
сохранились. Эта доработка после оценки явно записана в протоколе. Новый
двигатель восстанавливается и замораживается до тестирования; тестовые записи
никогда не обучают его. Оценка успеха включает отказы в знаменателе.

Это первые открытые измерения, знакомые небольшие публичные корпуса. GunPoint
описывает два типа движения двух актёров; это классификация целой записи,
а не потоковая обработка, понимание событий или перенос на неизвестных актёров.
Новая архитектура **уступает простым контролям** и не достигает своих порогов.
Проверки корректности конвейера не переименовывают эти FAIL в научный PASS.

Прежний прототипный режим цифр сохраняет свой результат 343/364 (94,23%). Он
отдельный, более успешный режим; его ответы не подставляются в новый двигатель.
Ограниченная память, одиночные деревья и строгая поддержка приобретённых
операций остаются ограничениями; вклад каждого в ошибки ещё не разделён
отдельными абляциями. Универсальный интеллект из этих результатов не следует.

## API и запуск

На холодном организме сначала включите native planning, online, vector learning
и induction, затем `enable_phase_primitives(PhasePrimitiveConfig::default())`.
Выделите дополнительные спящие ячейки для пулов. `phase_primitives` показывает
приобретённые определения и их происхождение, `phase_primitive_value` исполняет
физическую операцию, `phase_constructor_info` показывает обученные предпочтения.
`phase_induction_programs` показывает вызовы операций в программах действий.
Checkpoint v9 читает сохранённые v1–v8. Ни кадр, ни цель, ни разрешение актуатора
не становятся свежими фактами после загрузки.

```bash
cargo test --locked --release --test acquired_primitives --test real_programs -- --nocapture
cargo run --locked --release --example real_programs
cargo run --locked --release --example acquired_primitives -- learn /tmp/aeterna-motion.json
cargo run --locked --release --example acquired_primitives -- run /tmp/aeterna-motion.json
cargo run --locked --release --bin perception -- train tests/data/digits.csv /tmp/program-digits.json --programs
cargo run --locked --release --bin perception -- recognize /tmp/program-digits.json /path/to/digit.png
```

Команда `run` отдельным процессом проверяет замороженные прогнозы сигналов;
общий тест дополнительно проверяет фактическое исполнение через защищённый
runtime. Команда изображения использует двигатель, записанный в checkpoint;
новый режим может отказаться от ответа. Файлы записываются только по новому пути.
