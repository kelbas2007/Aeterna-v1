# Acquired operations and recorded-data contract before scoring

This open development extends optional program induction. No named Boolean
operations are preinstalled. Prospectively confirmed nonconstant programs can
be copied into a fixed physical library and called as inputs to later programs.
Definitions remain acquired graphs, not a Rust function selected by a label.
Copies retain their factual origin and support. A derived input is unavailable
outside the acquired definition's support; no numerical backup supplies it.
Calls form a bounded acyclic graph. Old definitions are retained as transforms;
their old association with an action is not assumed valid in a changed task.
Every new action program requires its own subsequent factual checks.

Candidate inputs now include acquired operations. Equal-loss construction ties
use physical preferences updated after actual outcomes. The generic interpreter,
loss, midpoint generation, finite search and local credit rule are inherited
Rust substrate. This is acquisition of composite instructions and limited
adaptation of construction, not elimination of inductive bias or invention of
arbitrary machine instructions. Full phase ownership remains unqualified.

Mechanism witnesses: empty cold library; acquire two-input interaction and reuse
it for three-input interaction; exact physical library cut/restore; learned
constructor preferences and their causal tie control; no imagined updates;
fixed allocation, checkpoint restore, earlier-only calls and atomic rejection of
cycles/invalid provenance. Retain first unsuccessful results if revisions occur.

Recorded-data evaluation uses the exact same program/library engine:

* Images: existing recorded 1797 8x8 digits, unchanged fixed split of 1433/364,
  all ten classes. One tuition pass, at most eleven actions per training image.
* Signals: original GunPoint train/test files, 50/150 actual recorded hand-motion
  series from two actors. Average each successive three samples (150 -> 50),
  normalize by a single min/max fitted on training records only and clip.
  Four tuition passes, at most three response/measurement roles, five actions
  per training episode. This is offline whole-record classification, not live
  streaming, clinical analysis or actor-independent generalization.

Recorded-data defaults set before scoring: 15 nodes/motor, depth 6, 128 search
expansions/fit, 128 facts/motor, child support 2, two subsequent program checks,
one leaf check, coverage 0.25, minimum outcome 0.6, margin 0.05, four primitive
slots and policy learning rate 0.02. Existing synthetic defaults are unchanged.
Motors are opaque and chosen by EvoPhase. Only factual PRE, POST and actual
outcome enter the core. Labels are held in the external environment. Controls
(32-example nearest neighbor and class centroids) receive the identical acquired
positive tuples. Freeze and restore before testing. Start with no features;
two actions maximum: acquired measurement then one terminal response. Include
abstentions in the denominator and report all actual action costs and errors.

Open usefulness targets: images >=60%, signals >=70% including abstentions.
No superiority criterion. If these targets fail, retain FAIL and report limits;
ordinary pipeline tests do not turn accuracy failures into qualification PASS.
The previously measured prototype image path is a separate control/regression,
never a fallback inside the program/library engine. No held-out-driven tuning.

## Post-score engineering clarification

The initial control adapter assumed the measurement role. It was corrected to acquire the unique observation-producing zero-success motor from the same factual tuples and explicitly count its action. Repeating with this correction retained every accuracy, error, abstention, engine action cost and checkpoint size. Controls used 728 actions on images and 300 on signals. Engine defaults, training data and declared usefulness gates are unchanged; both FAIL records remain. This is an openly revised evaluator, not an independent fresh qualification.
