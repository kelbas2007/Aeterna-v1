# Обратный вывод по приобретённым правилам

Разработка от 9 октября 2026 года. Опциональное расширение
[частичных наблюдений](PARTIAL_OBSERVATION.md) и
[круговых формул](EXPANDED_RULES.md), без нового sealed qualification.

## Что добавлено

После разрешённого фактического действия система использует подтверждённую
формулу для восстановления отсутствующего PRE. Например, для приобретённого
`post[0] = (pre[0] + pre[1]) mod 1`, известного `pre[0] = 0.3` и
измеренного `post[0] = 0.8` выводится гипотеза `pre[1] = 0.5`.
Затем восстановленный PRE проходит обычный физический readout, чтобы получить
гипотезы о скрытых значениях текущего POST.

При `post[0] = (2 * pre[1]) mod 1` и измерении `0.8` сохраняются оба
корня: `0.4` и `0.9`. Коэффициенты ±3 дают три корня. Остальные фактические
выходы того же действия могут отфильтровать варианты; иначе существующая
политика informative action выбирает действие, чьи видимые последствия
различают гипотезы.

## Интерфейс и границы факта

```rust
assert!(evo.enable_phase_partial_observation(PhasePartialConfig::default()));
assert!(evo.set_phase_inverse_inference(true));
let mut rt = ScientificRuntime::new(evo)?;
rt.observe_external_partial(&[Some(0.3), None])?;
rt.set_partial_goal(&[Some(0.8), None])?;
// Только step_partial с разрешённым внешним исполнителем приносит POST.
```

Настройка по умолчанию выключена и сохраняется в checkpoint v8.
Её изменение очищает текущий эпизод. `PhasePartialBeliefInfo::inverse`
содержит `PhaseInverseReport`: действие, ревизию правила, ссылки на его
фактические основания, измеренный POST и восстановленные варианты PRE.
Отчёт и эпизод не сохраняются на диск и не входят в fingerprint знаний.

Вывод всегда имеет `Authority::Imagined`. Он не заполняет `factual`, не
заменяет `None` нулём и не учитывается как подтверждение численного правила.
Обучение численным преобразованиям по-прежнему требует полностью измеренных
PRE и POST. Цель считается достигнутой только по измеренным полям последнего
POST, даже если скрытое значение было однозначно выведено.

Параметр сдвига читается из тех же физических связей, что и при прямом
прогнозе. Для двух входов нужны обе связи. Их отключение убирает поддержку
правила; изменение фазы меняет обратное решение. Запасного сдвига в отчёте,
формуле или отдельном решателе нет. Выбор формулы и решение уравнений
выполняет программный алгоритм; это гибридное расширение.

## Неопределённость и память

Решатель применяется к подтверждённым точным моделям. На каждой итерации
решаются только уравнения с одним неизвестным операндом. Несколько выходов
могут последовательно раскрыть другие операнды; число проходов ограничено
числом каналов. Уравнение `x + y = c` с обоими неизвестными оставляет
непрерывную неопределённость: корреляция между переменными отдельно не
кодируется.

Прежний `max_hypotheses` ограничивает варианты: по умолчанию 32, максимум
128. При переполнении строится охватывающее множество с неизвестными полями.
Допустимые корни не отбрасываются ради цели или экономии памяти. Такая
аппроксимация может помешать планированию. Противоречащие всем вариантам
фактические данные запускают прежний отзыв модели или временный veto при
замороженных знаниях; восстановление состояния оставляет только фактические
поля.

## Запуск с сохранением

Путь для `learn` должен ещё не существовать:

```bash
cargo run --locked --release --example inverse_inference -- learn /tmp/aeterna-inverse.json
cargo run --locked --release --example inverse_inference -- run /tmp/aeterna-inverse.json
```

Фактический результат двух отдельных процессов:

```text
mode=learn rule_actions=6 mask_actions=6 modular_roots=2 goal_actions=2 factual_goal=true frozen_unchanged=true
mode=run rule_actions=0 mask_actions=0 modular_roots=2 goal_actions=2 factual_goal=true frozen_unchanged=true
```

Правила и маски приобретаются из реальных переходов; готовые формулы,
источники, смещения и роли действий остаются у внешнего оценщика. Полное
приобретение в этом примере использует новые начальные состояния отдельных
проб. Частичная оценка проходит в одном эпизоде.

## Проверки

`tests/inverse_inference.rs` содержит семь направленных проверок:

| Проверка | Результат |
|---|---|
| 32 мира, перестановки каналов и действий, 256 новых задач | Обратный вывод 256/256, прежний прямой вывод 127/256, циклический выбор 128/256; всем доступно два действия на задачу |
| Коэффициенты ±2 и ±3 | Все корни сохранены, различающее фактическое измерение оставляет один вариант |
| Последовательный вывод по выходам; два неизвестных в сумме | Уравнения распространяют ограничения; непрерывное семейство остаётся неопределённым |
| Ёмкость одного варианта и обучение включено | Расширение до неизвестности, без обучения на выведенных числах |
| Отключение, сдвиг на π и точное восстановление каждой связи суммы | Вывод зависит от реальных приобретённых фазовых параметров |
| Нулевой корень и фактическое противоречие | Ноль сохраняется; восстановление не выдумывает скрытые данные |
| Диск, рестарт, цель, заблокированное действие и непригодный POST | Настройка сохраняется, эпизод исключён, источники вывода не подделываются |

В сравнении обе обучаемые системы получают одинаковые приобретённые правила
и маски; параметры заморожены. Циклический алгоритм использует те же
начальные состояния и фактические маски. Цели нетривиальны. Это открытый
детерминированный синтетический диагностический набор одного семейства,
не доказательство общего интеллекта или преимущества во всех средах.
