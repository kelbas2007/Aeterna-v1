# Расширенные семейства приобретённых правил

Development-расширение от 9 октября 2026 года. Дополняет
[базовый язык](LEARNED_RULES.md) и [неполные наблюдения](PARTIAL_OBSERVATION.md).
Широкий язык выбирается явно через `PhaseRuleLanguage::CircularAffine`.
Типы доступных операций заданы разработчиком; конкретная формула каждого
выхода выбирается по фактическим PRE/POST. Цели, скрытые коэффициенты,
идентификаторы мира и роли действий не участвуют в обучении.

## Семейства

Все значения являются круговыми координатами в `[0,1)`, все операции —
по модулю 1. Это не арифметика произвольных чисел вне этого диапазона.
`b` обозначает приобретённый сдвиг, `x` и `y` — различные входные каналы.

| Семейство | Возможная формула |
| --- | --- |
| Прежнее копирование/отражение со сдвигом | `±x + b` |
| Константа | `b` |
| Целочисленное усиление | `kx + b`, где `k ∈ {−3, −2, 2, 3}` |
| Сумма двух каналов | `x + y + b` или `−x − y + b` |
| Разность двух каналов | `x − y + b` или `−x + y + b` |

Разные выходы одного действия могут принадлежать разным семействам.
Кандидаты перебирают все допустимые источники и коэффициенты. Первый
фактический пример калибрует сдвиг каждого кандидата; последующие исключают
несовместимые варианты. Подтверждение по-прежнему требует единственного
кандидата на каждый выход и по умолчанию трёх различных PRE.
Три различающихся кадра сами по себе недостаточны: при `x == y` сумма
неотличима от `2x`. В таком случае модель остаётся неоднозначной, а следующий
действительно различающий опыт позволяет исключить лишние объяснения.

`phase_rule_formulas(action)` возвращает семейство и источники подтверждённых
формул. Эта диагностика не хранит дополнительной копии сдвига и не создаёт
фактов или разрешений на действие.

## Физические зависимости и память

Сдвиг хранится в основной `PhaseSynapse::phase_offset`. Для двух входов
создаётся вторая физическая связь: при первоначальной калибровке её сдвиг
равен нулю, а прогноз читает оба сдвига, веса и confidence. Для константы
используется связь от существующей bias/outcome ячейки; скрытый сенсорный
канал не заменяется нулём. Отключение любой необходимой связи делает
прогноз неподдержанным, изменение её фазы меняет результат.

Источники и дискретные коэффициенты являются структурными метаданными
кандидатов. Вычисление формулы, ведение гипотез и beam search остаются
программными. Это гибридная реализация с зависимостью от приобретённых
фазовых параметров, не полное EvoPhase cognitive ownership.

При ширине `w` на каждый выход приходится `2w² + 4w + 1` кандидат и
`4w² + 2w + 1` физическая связь. На все правила действует общий предел
32768 связей, проверяемый до мутации. Число выходных ячеек остаётся
`channels × actions`; структура не растёт с числом наблюдений. Базовый язык
сохраняет прежний бюджет `2 × channels² × actions`. Сохраняются ограничения
до 16 каналов/32 действий, лимит файла 16 MiB, ограниченные evidence и поиск.
В широком языке не всякая комбинация размерностей помещается в бюджет.

## Запуск и обновление уже приобретённой модели

```bash
cargo run --locked --release --example expanded_rules -- learn /tmp/aeterna-expanded.json
cargo run --locked --release --example expanded_rules -- run /tmp/aeterna-expanded.json
```

В облачной среде при необходимости сначала выполните
`source /workspace/.aeterna-env/activate.sh`. `learn` требует нового имени файла.
В [примере](https://github.com/kelbas2007/Aeterna-v1/blob/research/beyond-intel4/examples/expanded_rules.rs) все четыре моторных правила
приобретаются в одном непрерывном эпизоде; наблюдения получаются только
от внешнего мира. `run` начинает другой процесс, загружает модель,
отключает обучение, получает свежий кадр и решает новую задачу.

Пример проверен в двух отдельных процессах:

```text
mode=learn acquired_rules=4 families=5 acquisition_actions=12 frozen_goal=true goal_actions=3 stored_states=0 frozen_unchanged=true
mode=run acquired_rules=4 families=5 acquisition_actions=0 frozen_goal=true goal_actions=3 stored_states=0 frozen_unchanged=true
```

Для нового организма после включения native online режима:

```rust
evo.enable_phase_rule_learning_with_language(
    PhaseRuleConfig::default(), PhaseRuleLanguage::CircularAffine,
);
```

Для уже приобретённого базового правила:

```rust
let mut evo = EvoPhase::from_online_checkpoint(&bytes)?;
evo.set_planning_learning_enabled(true);
assert!(evo.expand_phase_rule_language());
```

Расширение допустимо при включённых обучении и structural growth, если
бюджета хватает. Оно сохраняет прежние физические параметры и адреса,
revision, наблюдения и их идентификаторы. Добавляются новые кандидаты,
проверенные только по сохранённым фактическим основаниям. Счётчики опыта
не увеличиваются; новые source IDs не выдумываются. Если новые формулы
также объясняют прежние кадры, подтверждение отзывается до различающего
фактического опыта. При freeze либо нехватке ресурса вызов возвращает
`false` без изменения модели. Расширение убирает текущий кадр и эпизодические
гипотезы, сохраняя приобретённые маски; нужно новое внешнее наблюдение.

Не вся история сохранена в ограниченном evidence: новые кандидаты проверяются
по текущим сохранённым примерам, а не по вытесненным кадрам. Это может оставить
дополнительную неоднозначность. При полном новом противоречии пересматривается
только затронутое действие; новая версия может выбрать другое семейство.

Checkpoint v7 сохраняет язык и адреса обеих физических связей. Читаются
v1–v6 с прежней семантикой; широкий язык нельзя объявить файлом v3.
Декодер проверяет полный состав кандидатов, источники, коэффициенты,
физические адреса и бюджет. Проверка структуры не удостоверяет автора файла.
После загрузки нужен свежий кадр; живые freeze и emergency stop сохраняются.

## Неполные наблюдения

Константа может предсказываться без видимых входов. Усиление требует своего
входа, сумма/разность — обоих. Отсутствие нужного операнда оставляет неизвестный
выход; он не считается нулём. Прежняя политика расширения множества гипотез
при превышении ёмкости сохраняется. [Обратный вывод](INVERSE_INFERENCE.md)
добавляет отдельную опцию восстановления скрытого PRE по фактическому POST.

[Условное обучение при шуме](ADAPTIVE_RULES.md) использует тот же словарь
формул в отдельном режиме полных наблюдений. Сочетание шумных условных
моделей с частичным обратным выводом пока не поддерживается.

Любой прогноз остаётся `Authority::Imagined`. Приобретение численного правила
требует полностью фактических PRE и POST; вычисленные значения не обучают
параметры. Даже известная константа не позволяет объявить текущую цель
достигнутой без измерения её требуемого канала.

## Проверки

[tests/expanded_rules.rs](https://github.com/kelbas2007/Aeterna-v1/blob/research/beyond-intel4/tests/expanded_rules.rs) содержит 10 новых
development-тестов:

| Проверка | Полученный результат |
| --- | --- |
| 32 мира, 3–5 каналов, 3–4 непрозрачных действия и смешанные семейства | 350 действий приобретения; правильно выбранные источники/коэффициенты на всех 451 выходах |
| Новые состояния и цели после загрузки, модель заморожена | 256/256 задач до трёх действий; начальные и конечные состояния отсутствуют в истории обучения; learned fingerprint неизменен |
| Независимое целочисленное вычисление каждого действия на новых значениях | Прогнозы совпадают в допуске; authority остаётся IMAGINED |
| Совпадающие входные каналы | Три различных PRE сохраняют неоднозначность; различающий фактический опыт подтверждает правило |
| Одинаковые примеры для прежнего и широкого языков | Прежний язык не подтверждает двухканальную формулу; широкий подтверждает и решает задачу |
| Разрыв обеих связей пары и связи константы; фазовый сдвиг π; точное восстановление | Прогноз/план нарушаются; восстановление возвращает результат |
| Замена суммы целочисленным усилением | Версия действия отозвана и приобретена заново; другая модель сохраняется |
| Скрытые входы, константа и неизвестная сумма после загрузки | Константа не требует подставного входа; сумма вызывает измерение; скрытые значения не обучают правило |
| Расширение уже подтверждённого базового правила | Параметры и счётчики сохраняются; новые альтернативы требуют дополнительного опыта |
| Повреждение v4, старый v3, бюджет, freeze, emergency stop и нелинейный контроль | Некорректные файлы/расширения отклоняются; размер сети не растёт от tuition; нелинейный контроль остаётся неподтверждённым |

В основном наборе среда начинает каждый учебный эпизод со свежего случайного
фактического состояния, а мотор выбирает организм. Это не доказательство
непрерывного cold discovery во всех 32 мирах. Отдельный непрерывный пример
проверяет один фиксированный мир. 256 целей — восемь задач для каждой из 32
моделей, а не 256 независимых обучений. Генератор, проверки и бюджеты открыты
и созданы вместе с реализацией; это не независимая научная квалификация.

Локальная команда `bash scripts/check.sh` прошла: 111 успешных test invocations,
0 failed, 8 ignored и 79 filtered в 27 запусках тестовых бинарников. Счётчики
включают повторяющиеся общие fixtures. После усиления проверки переноса масок
при обновлении модели этот тест отдельно прошёл в release. Примеры всех четырёх
режимов прошли сохранение и запуск в отдельных процессах. Проверены также
загрузка и выполнение настоящих файлов v3 от предыдущего этапа разработки.
Development CI включает новый набор и пример; удалённый workflow пока не запускался.
Компиляция всех целей и Clippy correctness для библиотеки также прошли.
Форматирование новых модулей, тестов и примеров проверено; прежние предупреждения
о стиле и неиспользуемом коде остаются.

Общий интеллект не создан. Не поддерживаются произведения каналов,
произвольные коэффициенты, условные области, шумовые/стохастические законы
и произвольные программы. Краткий набор фактов может случайно согласоваться
с моделью вне её области; подтверждение не является универсальным доказательством.
Поиск остаётся ограниченным и может не найти существующий путь. Исторические
INTEL-4 и отрицательный TE4 не пересматриваются этим расширением.
