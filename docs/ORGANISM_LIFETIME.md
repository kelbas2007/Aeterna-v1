# Общий жизненный цикл AETERNA

[Проверенный результат: одна жизнь через четыре интерфейса, полный аудит и сохранённое обучающееся состояние](ORGANISM_LIFETIME_RESULT.md).

`organism_init` создаёт один ScientificRuntime, U1 и Learner. Изображения,
сигналы и навигация поступают в него через один интерфейс фактических действий.
`external_reset` меняет наблюдение и рабочий контекст, сохраняя приобретённое.
`checkpoint` / `load` продолжают то же состояние, включая рекурсивный поиск.
Прогон сохраняет `one-organism.json.gz` с продолжающимся обучением и отдельно
`frozen-organism.json.gz` для неизменяемой проверки. Команда `freeze` необратимо
останавливает обучение этого состояния и не нужна для обычного продолжения.
При остановке посреди эпизода его незавершённая часть процесса развития
явно прерывается, а открытая поведенческая проба отклоняется. Фактические
наблюдения и стоимость сохраняются; метка завершённого успеха или неуспеха
из остановки не создаётся.

Завершённый эпизод передаёт фактические наблюдения и дисконтированную награду
в существующие RSP2 и механизм пересмотра оценщика траекторий. Для обучения
поисковой политики нужны различные измеренные входы минимум двух интерфейсов.
Разделы предложения, fresh, transfer и producer не пересекаются по входам.
Прошедшие проверку входы больше не становятся обучением следующих предложений.
Все прежние условия принятия RSP2, включая producer и retention, действуют.
Пространство операций и лимиты поиска остаются заданными разработчиком.
В общем режиме ручные `improve_recursive_search` и `freeze_recursive_search`
отклоняются до изменения состояния. Развитием управляет общий цикл; для его
остановки используется `freeze`, который согласованно останавливает ученика.

Пересмотр оценщика использует действующую политику того же RSP2. Сначала новая
программа должна улучшить прогнозы на последующих завершённых эпизодах.
Затем выполняется ограниченная проверка поведения в той же продолжающейся
жизни: до действий эпизоду назначается прежний или новый оценщик, сбалансированно
в случайном порядке внутри каждого интерфейса. Действия по-прежнему выбирает U1.
Каждая проба получает настоящие POST, награду и стоимость, а не ответ модели.

Для принятия нужны минимум 12 эпизодов каждой стороны, минимум четыре каждой
стороны на каждом известном при начале проверки интерфейсе, рост средней награды
минимум на 0,05, отсутствие регрессии по интерфейсам и не более 10% увеличения
средней стоимости. Через 64 эпизода недостаток доказательств означает отказ.
Прерывание эпизода не превращается в обучающий неуспех и отклоняет текущую
поведенческую пробу. Позднее опровержение прогнозного основания снимает оценщик.
Это ограниченное сравнение в меняющейся среде с общей обучающейся памятью;
оно не гарантирует улучшения любой будущей задачи.

Исторический `external_init` и параметрическая адаптация EXTERNAL5 сохранены
для совместимости. В `organism_init` отдельная адаптация EXTERNAL5 выключена:
применяется существующий RSP2, связанный с пересмотром оценщика.

Память процесса развития ограничена 512 примерами, 256 действиями незавершённого
эпизода, восемью попытками изменения поисковой политики и тремя поведенческими
пробами. На пару интерфейсов приходится максимум две попытки изменения RSP2,
на интерфейс — три поиска оценщика (до 24 за жизнь). Это сохраняет ресурс для
следующих сред. Интеграция имеет конечный бюджет; это не бесконечное обучение.

## Проверка всей жизни

```bash
cargo test --locked --test organism_lifetime
CARGO_PROFILE_RELEASE_LTO=false CARGO_PROFILE_RELEASE_CODEGEN_UNITS=16 \
  cargo build --release --locked --bin aeterna-v1
python scripts/run_organism_lifetime.py --binary target/release/aeterna-v1 \
  --data DATA_DIRECTORY --output NEW_RESULT_DIRECTORY
python scripts/audit_organism_lifetime.py --results NEW_RESULT_DIRECTORY \
  --data DATA_DIRECTORY --output NEW_RESULT_DIRECTORY/audit.json
python scripts/verify_organism_continuation.py \
  --binary NEW_RESULT_DIRECTORY/frozen-aeterna-v1 \
  --checkpoint NEW_RESULT_DIRECTORY/organism/one-organism.json.gz \
  --data DATA_DIRECTORY --output NEW_CONTINUATION_DIRECTORY
```

Один экземпляр проходит изображения → сохранение/восстановление → сигналы →
два навигационных мира → возврат к изображениям. Счётчики фактических действий,
стоимости и состояния проверяются на каждом переходе. Отдельный аудитор
повторяет каждый сенсорный POST по исходным файлам, каждый переход MiniGrid
по seed и действиям, а также проверяет доступные моторы и границу восстановления.
Адаптер не передаёт
RSP2 готовых программ, учебных задач, вердиктов принятия или расписания моторов.

Сравниваются общий организм, тот же организм без изменения поисковой политики
и прежняя конфигурация EXTERNAL5. Данные, доступные действия и их предельные
бюджеты одинаковы; фактические измерения зависят от выбранных действий.
Используются только обучающие разделы Fashion-MNIST / UCI HAR и навигационные
development-seeds 850000+. Это разработческая проверка связности и поведения,
не независимый слепой экзамен; прежние результаты EXTERNAL5 не переоцениваются.
