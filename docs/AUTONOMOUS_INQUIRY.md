# Автономное исследование в AETERNA-v1

Механизм связывает противоречие, внутренний вопрос, прогноз эксперимента,
выбор действия, фактическое свидетельство и пересмотр применимости знания
в одном `ScientificRuntime`. Его память и незавершённый вопрос входят в
обычную контрольную точку организма.

Это ограниченный механизм исследования применимости двух приобретённых
контекстных моделей. Он не является доказательством общего интеллекта,
сознания, самостоятельного изобретения произвольных теорий или способности
решать любые задачи. Основную цель задаёт среда или пользователь; вопрос о
неверном объяснении возникает из собственного опыта организма.

## Что происходит внутри одного решения

1. **Прогноз.** Из фактической памяти извлекаются распределения последствий
   доступных действий. Отсутствие данных остаётся неизвестностью.
2. **Противоречие.** После реального действия проверяется, нарушен ли
   поддержанный опытом, достаточно уверенный прогноз. Низкая вероятность
   отдельного значения шумового датчика сама по себе не означает ошибку
   объяснения.
3. **Вопрос.** Система сохраняет событие, ожидавшееся и наблюдавшееся
   последствие, поддержку старого прогноза и конкурирующие предположения о
   применимости моделей. Обычный перезапуск эпизода не стирает вопрос.
4. **Исследование.** На основе уже приобретённых моделей система оценивает,
   какие доступные действия и короткие последовательности могут различить
   объяснения. Ожидаемая информация учитывается отдельно от ожидаемого
   достижения основной цели и стоимости действий.
5. **Выбор и действие.** Исследовательский план становится предложением
   существующему U1. После его выбора и разрешения Human Protection
   фиксируется свидетельство решения **до** получения POST. Воображаемая
   ветвь не превращается в фактический опыт.
6. **Пересмотр.** Только реальный POST обновляет свидетельства о применимости
   моделей. Разрешение вопроса и фактическое выполнение эксперимента
   учитываются отдельно. Неразрешённый вопрос может истечь по пределу
   ресурсов; истечение не считается найденным объяснением.
7. **Продолжение.** Новая применимость используется последующими решениями.
   При сохранении остаются приобретённые данные, состояние вопроса,
   контроль выбора действий и накопленная стоимость жизни.

## Запуск одного организма

Сборка приложения:

```sh
cargo build --locked --release --bin aeterna-v1
target/release/aeterna-v1 --jsonl
```

В Windows имя исполняемого файла заканчивается на `.exe`.

Пример инициализации для виртуальной среды с двумя наблюдаемыми значениями
и пятью исполнительными командами:

```json
{"op":"autonomous_init","width":2,"actions":5,"observation":[0,101],"planning_depth":5,"planning_work":120000,"max_external_cost":100000}
```

`autonomous_init` создаёт тот же организм и совместно включает существующее
самостоятельное управление, учёт самостоятельного выбора, причинную память,
обычное контекстное заключение и автономное исследование. Этот путь удобен
для запуска без цепочки отдельных команд настройки.

Цель и доступные действия передаются обычной командой:

```json
{"op":"step","goal":[null,829],"available":[true,true,true,true,true],"remaining_actions":5}
```

Приложение возвращает выбранную команду, например
`{"type":"action","action":2}`. В этот момент адаптер должен **исполнить
именно выбранную команду** и вернуть действительное наблюдение, стоимость и
награду. Приведённые числовые коды — пример интерфейса, а не встроенное
значение датчиков или ожидаемый правильный ответ.

```json
{"op":"post","result":{"observation":[0,307],"cost":1,"reward":0.0}}
```

POST выше показывает форму сообщения. Его нельзя подставлять вместо
реального результата среды. После подтверждения действия следующий `step`
продолжает тот же организм. Новое реальное начальное наблюдение следующего
эпизода передаётся так:

```json
{"op":"observe_restart","observation":[0,101]}
```

Эта команда очищает историю текущего эпизода, сохраняя знания и открытый
вопрос. Она не создаёт фактического перехода и не даёт свидетельства в
пользу гипотезы.

Диагностика и сохранение:

```json
{"op":"inquiry_report"}
{"op":"report"}
{"op":"checkpoint"}
```

В ответе `checkpoint` поле `checkpoint` содержит полный JSON организма в
виде строки. Для продолжения в новом процессе передайте эту строку через
`{"op":"load","checkpoint":"..."}`. Сохранить только отчёт недостаточно:
отчёт не содержит всей приобретённой памяти и состояния управления.

## Подключение к существующей жизни

Для уже загруженного организма с причинной памятью глубины 3:

```json
{"op":"enable_autonomous_inquiry","mode":"active"}
```

Включение сохраняет фактическую память. Если контекстное заключение ещё не
включено, применяется обычный вариант; несовместимый фазовый вариант,
повторное включение и изменение уже замороженного организма отклоняются.

Для сохранённой жизни можно сразу создать отдельную проверенную контрольную
точку с включённым механизмом:

```sh
python3 scripts/upgrade_autonomous_inquiry.py --input old-state.json --output inquiry-state.json --binary target/release/aeterna-v1
```

Утилита проверяет сохранность приобретённой памяти и состояния управления,
загружает результат в новом процессе и требует точного воспроизведения.
Она не выполняет действий среды и не перезаписывает исходный файл.

Rust API:

```rust
use aeterna_v1::construction::causal_memory::InquiryMode;

runtime.enable_constructing_autonomous_inquiry(InquiryMode::Active)?;
let report = runtime.construction_learner().unwrap().causal_inquiry_report();
let state = runtime.checkpoint_constructing()?;
```

Режим `ObserveOnly` ведёт вопросы и диагностику, но не меняет выбор действия
исследовательским предложением. Он нужен для причинного сравнения с полным
режимом. Отсутствие механизма сохраняет прежнюю сериализацию и поведение
старых контрольных точек.

## Как читать свидетельства

- **Открытый вопрос** означает замеченное противоречие, а не доказанную
  смену правила мира.
- **Предложение эксперимента** не означает, что U1 выбрал или выполнил его.
- `UnifiedStep.inquiry_decision` содержит прогноз фактически выбранного
  исследовательского действия, зафиксированный до его результата.
- **Фактический эксперимент** означает полученный реальный POST; это ещё не
  подтверждение правильности одной из гипотез.
- **Разрешённый вопрос** означает достаточное накопленное свидетельство
  внутри этих ограниченных моделей. Внешняя оценка проверяет, привело ли
  оно к правильному поведению.
- **Достижение цели** подтверждается средой отдельно от уверенности
  организма и его внутреннего отчёта.

Заморозка обучения не останавливает восприятие и текущие выводы. При этом
приобретённые таблицы, число обучающих переходов и их отпечаток остаются
неизменными. Доступность действий, предел стоимости и защита каждого
исполнения продолжают действовать.

Текущая реализация удерживает один открытый вопрос и две контекстные модели.
Вопрос ограничен 192 последующими фактическими переходами. Прогноз
исследования содержит не более восьми явных исходов; более сложное
распределение остаётся неизвестным для этого механизма. Для состояния
исследования резервируются 32 КиБ внутри общего ограничения памяти.
Поиск сохраняет установленные ограничения глубины, числа состояний,
вычислительной работы и внешней стоимости. Это явные инженерные пределы,
а не утверждение о неограниченном мышлении.

Проверенный исполнительный путь использует явно заданную символическую
цель в `step`. Режимы внешней сенсорной награды имеют собственный выбор
предложения в `external_reward`; текущие результаты не подтверждают такую
же работу исследования во всех этих режимах. При отсутствии символической
цели оптимистичное предложение памяти наград может получить приоритет до
вызова исследовательского планирования.

## Проверка механизма

Инженерные проверки:

```sh
cargo test --locked --release --lib inquiry_
cargo test --locked --release --test autonomous_inquiry_contract
```

Поведенческий протокол находится в
[`experiments/AUTONOMOUS_INQUIRY_20261123_PROTOCOL.md`](experiments/AUTONOMOUS_INQUIRY_20261123_PROTOCOL.md).
Он сравнивает обычную контекстную память, активное исследование и
`ObserveOnly` из идентичных приобретённых контрольных точек. Все команды
всегда доступны, их назначения скрыты от организма, а моменты смены правил не
передаются его коду. Отдельно оцениваются цельная цепочка исследования,
практическая польза, стоимость действий и поведение без смены правила.

Источник механизма — `src/construction/inquiry.rs`, интеграция с приобретённой
памятью — `src/construction/causal_memory.rs`, граница единственного выбора и
защищённого исполнения — `src/unified_runtime.rs`. Прежние отрицательные
эксперименты и их критерии сохраняются.
