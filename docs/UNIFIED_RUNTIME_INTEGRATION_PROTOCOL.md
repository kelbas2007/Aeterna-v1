## Purpose

This is not a new cognitive mechanism/gate.

It only assembles the already-qualified U1-U3 architecture into the persistent protected runtime that INTEL-2 will use.

INTEL-2 MUST NOT call the legacy fixed-priority `ScientificRuntime::propose()` as its cognitive authority.

## Unified runtime requirements

For every decision:

1. obtain current raw factual state and raw goal;
2. enumerate every currently available qualified operation without selecting by class:
   - contextual refinement;
   - perceptual refinement;
   - compositional refinement;
   - rival/law discrimination;
   - goal-directed action;
   - general epistemic exploration;
3. derive bounded task-agnostic proposal fields from carrier state;
4. persistent explanatory structures use stable physical/provenance IDs in U2 ecology;
5. proposals enter one U1/U2/U3 competition;
6. only the winning opaque action proceeds to Human Protection;
7. blocked actions create no fact;
8. one executed action produces one factual POST and one shared factual fanout.

Enumeration order may be authored; **authority order may not**.

## Generic proposal fields

The runtime may compute only carrier-derived generic quantities:
- predicted goal progress/value;
- direct/reachable epistemic novelty;
- rival/contradiction pressure;
- learned evidence/confidence, including U2 authority;
- generic action/computation economy.

No module-type constant, task ID, world ID or class bonus.

Unavailable quantities are 0, not host-invented priors.

## Stable candidate identity

Persistent explanation candidates use IDs derived only from their physical/provenance structure, such as learned synapse/cell addresses and opaque action binding.

The same structure must keep the same ID across decisions/checkpoints.

A task/world label must never enter candidate identity.

Nonpersistent immediate proposals may use opaque per-structure IDs but cannot receive stored U2 authority unless their physical provenance is stable.

## Factual utility / credit

Online U2 usefulness must be derived generically from the actual result of the selected operation, not from an evaluator-supplied correct-class label.

Allowed signals:
- factual goal progress / reaching goal;
- acquired new transition or structural fact;
- reduction of supported contradiction/rival uncertainty;
- evidence increase/promotion of a structure;
- factual failure/no gain.

The evaluator supplies raw POST and bounded task outcome only; it does not name which reasoning class deserved credit.
