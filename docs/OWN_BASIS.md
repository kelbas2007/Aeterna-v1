# Собственная обучаемая основа AETERNA

Основа обучается в том же `ScientificRuntime`, что хранит память организма и
исполняет действия через U1. Готовая нейросеть, сторонние веса и модельный API
не используются. Линейные параметры начинают с нуля; новые нелинейные
вычисления — со случайных весов из сохраняемого seed.

Каждый навык задаётся явной учебной инструкцией. Он читает исходные пиксели или
отсчёты сигнала, а не только прежние 32 сводных показателя. Навыки одного
физического формата разделяют библиотеку обученных признаков. Новая функция
вычисляет tanh от исходных координат и ранее приобретённых функций. Число
функций может расти. Принятые определения сохраняются неизменными, поэтому
обучение другой инструкции не переписывает прежний навык.

Это первый этап собственной основы: обучение представлений и их применение
в общем организме. Размеченный учебный пример является помощью учителя.
Он не засчитывается как автономное открытие, действие среды или поколение
самоизменения RSP2. Алгоритм обучения и исходная арифметика заданы программой.

## Использование

Запуск: `cargo run --release --bin aeterna-v1 -- --jsonl`.
После обычного `organism_init`:

- `organism_enable_own_basis`: `frame` и необязательный `config`. Пустой config
  создаёт необученную основу; `grow: false` отключает рост для сравнения.
- `basis_teach`: `skill`, `frame`, `label`, `source_id`. Явный учебный факт;
  ответ содержит прогноз до обучения и учтённую вычислительную работу.
- `basis_predict`: `skill`, `frame`. Возвращает распределение известных понятий.
- `basis_goal`: `goal: {skill, answers: [{motor, concept}, ...]}`. Это инструкция
  связывания ответов с моторами, одинаковая для всех наблюдений задачи.
- `external_reset`, затем `external_step` и фактический `post`: обычное
  исполнение через U1. Оценки нового навыка определяют смысл этой цели для
  всех предложений непосредственного действия.
- `basis_report`, `organism_report`, `checkpoint`, `load`: общая диагностика
  и продолжение жизни. Состояние с основой использует checkpoint v3; старые
  состояния v1/v2 продолжают читаться.
- `basis_goal` с `goal: null` очищает инструкцию; `freeze` прекращает обучение.

Название навыка — инструкция пользователя. Namespace, имя файла и правильный
мотор не являются входными признаками. Метка `basis_teach` передаётся отдельно
и не может незаметно попасть в тестовое наблюдение.

## Рост и сохранение

Через 256 новых входов система может предложить следующий блок признаков.
Он обучается параллельно действующей модели на общей ограниченной памяти.
После прогрева сравниваются прогнозы на 128 последующих разных входах,
каждый до обучения на текущей метке. Допуск требует уменьшения log-loss
минимум на 5% и отсутствия снижения числа правильных ответов. Неудачный
кандидат удаляется, его расходы сохраняются. При допуске общего блока
кандидаты других навыков, ссылающиеся на прежний префикс, отменяются.

Другие головки не изменяются. Их числовые ответы проверяются до и после
следующей учебной стадии. Это обеспечивает сохранение разных инструкций;
переобучение той же инструкции может изменить её ответы.

Память ограничена числом записей, размером их f32-данных и числом параметров.
Текстовый checkpoint дополнительно ограничен 32 MiB. `work` — объявленный
счётчик оценок вычислительной работы, не замер всех инструкций процессора.
Кандидат, действующая модель и репетиции делят один предел работы на урок.

## Воспроизведение

`cargo test --release --test own_basis_organism` проверяет общий checkpoint,
сохранение старого навыка, запрет обучения после freeze, независимость от
namespace и фактический выбор U1.

Реальные данные подготавливаются существующими средствами проекта. Отдельный
запуск сравнивает два полных организма с одинаковыми уроками и бюджетами:

```sh
python scripts/own_basis_lifetime.py --binary target/release/aeterna-v1 \
  --data /path/to/external5-data --output /path/to/new-results
```

Последовательность: Fashion-MNIST → исходные сигналы UCI HAR → MNIST →
возврат к прежним навыкам. Учебные метки берутся только из train. Проверка
использует фиксированный конец официальных test-разделов; эти корпуса уже
использовались проектом, поэтому такой запуск не называется слепой новой
проверкой. В тестовых действиях обратная связь по правильности скрыта от
всего организма; POST получает нейтральную награду. Считаются ответы U1,
расхождение с распознавателем, сохранение ответов и затраты всех кандидатов.
`--develop` использует отложенные train-записи для отладки.

Файлы `life.jsonl.gz` содержат уроки, запросы и фактические действия. Скрипт
`replay_learning_world.py` воспроизводит их и проверяет конечное состояние.
