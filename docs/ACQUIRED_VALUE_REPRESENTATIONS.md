# Обучаемые представления и последствия действий

Этот opt-in режим расширяет [контекстные ценности](CONTEXT_VALUE_LEARNING.md).
Он использует один общий конструктор для разных размерностей бинарного входа
и непрозрачных моторов. Обучение идёт после собственных фактических действий
и проверенного POST; класс, правильный мотор и карта агенту не передаются.

## Включение

После `init`, до первого `reset`:

```json
{"cmd":"general_policy"}
{"cmd":"context_value_learning"}
{"cmd":"value_abstraction"}
```

Для задач с памятью перед `context_value_learning` дополнительно включите
`developmental_memory` и, при соответствующем публичном формате сенсоров,
`relational_workspace`. Каждый ответ должен подтвердить `accepted: true`.
Позднее включение обобщения отклоняется: у старых хешей нет исходных измерений.

## Что приобретается

Из фактического опыта сохраняются значения и наблюдавшиеся переходы. Оптимальные
посещённые действия положительных MODEL-оценок задают примеры для обучения
предикатов. Часть собственных обучающих примеров используется для выбора
между деревом и сравнением с тремя аналогами. Среди группировок битов шириной
1..8 выбирается та, которая лучше предсказывает приобретённое действие.
Ширина кодирования пикселя или сигнала не передаётся конструктору.

Отдельно каждый мотор приобретает модель изменения наблюдения. Если опыт
показывает устойчивую связь одного мотора с завершением разных эпизодов и
наблюдаемые последствия действий, незнакомые состояния могут использовать
эти модели и предпочтения из успешных траекторий. Индексы признаков,
прогнозы последствий и предпочтения моторов приобретаются; маршрута,
названий объектов или значения «вперёд/поворот» в этом конструкторе нет.
Порог устойчивости и формула объединения — явно написанный общий inductive
bias. Такой режим не доказывает универсальную адаптацию к новым законам.

Известные точные состояния сохраняют прежнюю политику. Новые правила и
сравнения работают при замороженном использовании неизвестных состояний.
`status` сообщает число узлов, выбранную группировку, число аналогов,
внутреннюю проверку и наличие модели последствий. `value_predicates`
возвращает приобретённые предикатные программы для диагностики.

## Ограничения и контроль

- До 2048 состояний с LRU-вытеснением, 512 аналогов, 255 узлов дерева.
- До 63 узлов модели последствий на мотор, до 32 моторов.
- Внутренняя проверка до 64 примеров; количественные оценки на маленькой
  выборке остаются неопределёнными. Выбранная группировка не обязана совпадать
  с истинным форматом источника измерений.
- MODEL-предсказания не становятся дополнительными REAL-наградами или опытами.
- При `learning: false` приобретённые параметры остаются неизменными;
  попытки текущего эпизода поддерживают ограниченное восстановление из циклов.

Копирование native checkpoint сохраняет знания внутри процесса. Дисковый
Online v9 пока не сериализует этот head. Когнитивное восстановление сохраняет
внешнюю защиту и журнал и требует нового фактического наблюдения. Диагностическая
лесия выполняется в адаптере над копией carrier, затем проходит этот же
проверяемый путь восстановления; runtime не выполняет control-вмешательства.

Физическая связь необходима для доступа к приобретённому обобщению и мотору.
CART, подбор группировок, расстояния, статистика и TD/replay всё ещё реализованы
программно. Это обучение представлений и моделей внутри заданного субстрата,
не самостоятельное изобретение базовых примитивов или полное EvoPhase ownership.

[Первая внешняя проверка: FAIL](VALUE_RULE_TRANSFER1_RESULT.md) ·
[вторая проверка: протокол](VALUE_RULE_TRANSFER2_PROTOCOL.md).
Внешние проверки запускаются вручную. Повторные испытания уже использованных
реальных записей — открытая итерационная валидация, не независимая квалификация.
