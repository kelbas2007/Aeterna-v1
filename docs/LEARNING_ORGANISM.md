# Общий обучающийся организм: рабочий контур v2

Реализован первый полный контур из
[архитектурного решения](decisions/0001-learning-organism.md): исходные
наблюдения → обучаемое состояние истории → прогноз последствий и полезности →
предложения существующему U1 → фактический POST → обучение и консолидация.
Он работает внутри прежнего `ScientificRuntime`, сохраняется вместе с ним
и может продолжать старую жизнь. Отдельного актора или исполняемого «мозга» нет.

Это реализация архитектуры и доступ к реальным данным. Общий интеллект,
новый универсальный алгоритм и превосходство рекурсивного производителя
этим изменением не заявляются.

## Что изменилось в действующем пути

| Функция | Реализация |
|---|---|
| Восприятие | Все предъявленные пиксели и отсчёты поступают в обучаемые координатные проекции. Позиция и временной порядок сохраняются. Namespace не является входным признаком модели. |
| Совместные наблюдения | `multimodal` объединяет изображение, сигналы и/или сцену одного события. Разные сенсоры используют общую историю и динамику. Нормировка и выбор реконструируемых координат учитывают физические модальности. |
| Рабочая память | Обучаемая рекуррентная сеть обрабатывает ограниченную историю наблюдений и реальных действий. Одинаковый текущий кадр может иметь разные значения после разных историй. |
| Модель последствий | Два bootstrap-взвешенных предиктора, общая обучаемая реконструкция, прогноз награды и ограниченной дисконтированной полезности. Прогноз будущего состояния согласуется с тем же пространством представлений. |
| Быстрое воспоминание | Предыдущие фактические исходы того же сырого контекста уточняют прогноз. Ключ включает историю и действия, исключает namespace. Это эпизодическое свидетельство; совпадение не объявляется универсальным законом. |
| Медленные знания | Параметры кодировщика, рекуррентных связей, динамики и прогноза исхода меняются по реальному опыту и внутренним повторам. Реконструкция исходных данных противодействует вырождению представления; гарантии полезности или отсутствия любого схлопывания нет. |
| Консолидация | Ограниченная память хранит сырые фрагменты с происхождением событий; выбор повторов сочетает равномерный доступ и наблюдаемый прогресс. Параметры реально обновляются. Повторы не увеличивают счётчик фактических переходов. |
| Цели | Желаемое наблюдение хранится отдельно от фактов. Модель оценивает приближение к нему; U1 получает дополнительный кредит достижения только по фактическому наблюдению. Смена цели не обучает модель на выдуманном примере. |
| Выбор действия | Прогнозы входят в прежний пятикомпонентный контракт предложений. Единственным физическим выбором остаётся U1; выполняется только разрешённый callback и один действительный POST. |
| Сохранение | Схема v2 содержит модель, память, рабочий контекст, цель, RNG, версии представлений и ресурсные счётчики. Прежняя схема v1 остаётся побайтово совместимой при отсутствии нового состояния. |
| Существующее развитие | RSP2, VM и общий координатор сохраняются. Учебные задачи RSP2 теперь получают приобретённую библиотеку ученика вместо безусловно пустой. |

Обучающаяся модель является программной рекуррентной сетью на Rust.
Градиенты распространяются через сохранённый контекст, чтобы менять входные
проекции и рекуррентные связи, а не только выходной оценщик. Её наличие
не означает автоматического включения всех исторических native-режимов.

## Запуск через канонический JSONL

Сборка использует прежний `Cargo.lock` и Rust 1.99.0:

```bash
cargo build --release --locked --bin aeterna-v1
target/release/aeterna-v1 --jsonl
```

Пример первой строки для сигналов:

```json
{"op":"organism_init","learning_world":{},"frame":{"kind":"signals","namespace":1,"channels":[[0.1,0.2,0.3],null,null,null,null,null,null,null,null]}}
```

Далее действует прежний протокол: `external_step` с доступными моторами
и ценой → одно намерение `action` → ответ адаптера `post` с действительно
полученными `frame`, `cost`, `reward`. Значение reward должно лежать в [-1, 1].
Конец эпизода обозначается `external_episode_end`; смена начального
наблюдения — `external_reset`. Обучение продолжается между эпизодами.

Формат совместного наблюдения:

```json
{"kind":"multimodal","namespace":1,"frames":[{"kind":"image","namespace":1,"pixels":[[0,255,0,255,0,255],[255,0,255,0,255,0],[0,255,0,255,0,255],[255,0,255,0,255,0],[0,255,0,255,0,255]]},{"kind":"signals","namespace":1,"channels":[[0.1,0.2],null,null,null,null,null,null,null,null]}]}
```

Допустимо до трёх разных физических модальностей с одним namespace.
Вложенные пакеты и повтор одной модальности отклоняются. Старый 32-мерный
кодировщик формирует только совместимое представление для прежних частей;
обучаемая модель получает исходные дочерние наблюдения.

Команды управления:

| Запрос | Назначение |
|---|---|
| `{"op":"learning_world_report"}` | Знания, рабочее состояние, прогнозы, ошибки до обновления и расход ресурсов. |
| `{"op":"set_learning_world_goal","frame":...,"tolerance":0.01}` | Желаемое наблюдение в уже знакомом сенсорном формате. Это цель, не факт среды. |
| `{"op":"set_learning_world_goal","frame":null}` | Вернуться к выбору по внешней полезности и неопределённости. |
| `{"op":"checkpoint"}` / `{"op":"load","checkpoint":"..."}` | Сохранение и продолжение общей жизни. |
| `{"op":"freeze"}` | Остановить изменения знаний всех частей; восприятие и обновление рабочего контекста продолжаются. |

Для миграции существующего v1 после `load`:

```json
{"op":"organism_enable_learning_world","config":{},"frame":{"kind":"signals","namespace":1,"channels":[[0.1,0.2,0.3],null,null,null,null,null,null,null,null]}}
```

Нужно передать фактическое текущее наблюдение. Прежние факты, навыки,
контроллер, затраты и RSP2 сохраняются. Новый счётчик `attached_after_event`
указывает точку подключения. Отброшенные когда-то пиксели не восстанавливаются
из старых 30 средних и не выдаются за обучающие данные нового кодировщика.

Без `learning_world` сохраняется прежний путь v1 для воспроизведения
опубликованных жизней и сравнения. Создавать независимый экземпляр модели
для каждого корпуса или каждого эпизода не требуется.

## Реальные файлы наблюдений

[learning_world_stream.py](../scripts/learning_world_stream.py) принимает JSONL
с записями вида:

```json
{"pre":{"kind":"signals","namespace":1,"channels":[[0.1,0.2],null,null,null,null,null,null,null,null]},"action":0,"post":{"kind":"signals","namespace":1,"channels":[[0.3,0.4],null,null,null,null,null,null,null,null]},"reward":0.0,"cost":1,"episode_start":true,"provenance":{"source":"my-recording"}}
```

Внутри непрерывного фрагмента PRE следующей записи должен совпадать с POST
предыдущей. `episode_start` объявляет границу записи, `terminal` — настоящий
конец эпизода. Конец файла сам по себе не превращается в терминальный исход.

```bash
python scripts/learning_world_stream.py --binary target/release/aeterna-v1 \
  --events observations.jsonl --output life-1 --limit 32
python scripts/learning_world_stream.py --binary target/release/aeterna-v1 \
  --events observations.jsonl --offset 32 --limit 32 \
  --checkpoint life-1/one-organism.json.gz --output life-2
```

Исторически записанный мотор является единственным предложенным мотором:
его исход не приписывается невыполненной альтернативе. Это получение знаний
из записи, а не доказательство самостоятельного управления физическим миром.
Для живого взаимодействия адаптер передаёт все реально доступные действия.

Подготовка потока из настоящих инерциальных записей UCI HAR:

```bash
python scripts/prepare_learning_world_signals.py --archive /path/to/uci-har.zip \
  --output observations.jsonl --count 64
```

Используются девять исходных сигналов обучающей части. Метки активности
и идентификаторы людей не декодируются. Операция чтения раскрывает вторую
половину действительно записанного окна после первой; физические действия
человека этим адаптером не моделируются и не выдумываются.

## Самостоятельные действия во внешней среде

Для рабочего примера подключения внешней среды есть
[адаптер Gymnasium Pendulum](../scripts/run_learning_world_environment.py):

```bash
python scripts/run_learning_world_environment.py --binary target/release/aeterna-v1 \
  --checkpoint life-1/one-organism.json.gz --output control-life --episodes 3 --steps 128
```

Он продолжает тот же сохранённый организм. Одно наблюдение содержит камеру
32×32 и три публичных сигнальных значения. Адаптер знает соответствие моторов
моментам силы; организм получает непрозрачные каналы, наблюдения и фактическую
награду. Готовая политика и скрытое состояние `env.unwrapped.state` не передаются.
Это внешний сторонний **симулятор**, не физический робот и не независимая
квалификация интеллекта. Исходная награда и её преобразование опубликованы.

Оба инструмента сохраняют `starting-organism.json.gz`, `one-organism.json.gz`,
полный журнал и `summary.json`. Полное программное воспроизведение:

```bash
python scripts/replay_learning_world.py --binary target/release/aeterna-v1 \
  --results control-life --output replay-proof
```

Проверяются каждое намерение, весь ответ commit и побайтовое конечное состояние.
Новый физический опыт при этом не приобретается.

## Ресурсы, заморозка и происхождение

По умолчанию: 16 скрытых компонент, шесть наблюдений рабочего контекста,
до 8192 координат и значений в предъявленном кадре, до 128 эпизодических
фрагментов с резервом 4 MiB, до двух повторов после POST. Общий checkpoint
ограничен прежними 32 MiB. Это не бесконечная точная память.

`work_per_step` ограничивает оплаченные вычислительные операции модели;
профиль обязан оставлять резерв на восприятие. Если места для обновления
не хватает, оно пропускается и отражается в `budget_skipped_updates`.
Не представленные из-за ёмкости координаты учитываются отдельно. Оценки
работы являются консервативными единицами алгоритма, не измерением всех
машинных инструкций. Сравнение вычислительной эффективности требует также
времени и памяти процессов.

Память повторов содержит исходные фрагменты, а не старые embeddings.
Контекст обрабатывается текущими весами после обновления представления;
в checkpoint сохраняется его версия. Цели и текущий контекст отличаются
от обученных знаний. `learned_fingerprint` при заморозке сохраняется,
несмотря на новые восприятия и фактические действия.

Полные журналы инструментов — отдельные исследовательские артефакты.
Их размер растёт с числом записанных наблюдений и не является размером
памяти организма. Для длительных потоков инструмент сохраняет ограниченные
порции, продолжение идёт через checkpoint и `--offset`.

## Что ещё требует отдельной реализации и проверки

Механизм обучения и его операции остаются реализованными разработчиком.
Новые веса, состояния и прогнозы приобретаются в жизни; это не означает
изобретения нового вычислительного примитива или алгоритма обучения.

Не завершены этапы 3–4 ADR: общий перенос библиотеки приобретаемых навыков,
исправление вероятностной постановки всех задач RSP2, доказанное улучшение
следующего производителя и независимая длительная внешняя оценка.
Рекуррентная рабочая память сама по себе рекурсивным самоулучшением не является.
Информационная ценность сейчас оценивается эвристикой ансамбля и поддержки;
калиброванный оптимальный выбор экспериментов не заявляется.

Проверки текущего контура и реальных запусков опубликованы в
[результате реализации](LEARNING_ORGANISM_RESULT.md).
