# Обучение правилам и самостоятельная проверка гипотез

Экспериментальное расширение ветки `codex/autonomous-learning`, 8 октября
2026 года. Оно развивает идеи из [обзора локального проекта](LOCAL_PROJECT_IDEAS.md)
и дополняет [режим online](ONLINE_LEARNING.md) отдельным режимом правил.
Исторические INTEL-4 и TE4 результаты не изменены.

Расширение от 9 октября: [новые семейства правил](EXPANDED_RULES.md)
добавляет константы, целочисленные усиления и суммы/разности двух каналов.
Описанный здесь базовый язык остаётся режимом по умолчанию.

## Что система теперь умеет

- Выводить преобразование каналов из фактических результатов действий.
- Держать несколько объяснений, выбирать действие, различающее их,
  и учитывать новое наблюдение только после исполнения.
- Применять подтверждённое правило к новому значению, для которого
  не создавался рецептор и не запоминался отдельный переход.
- Строить последовательность действий к новой цели из таких прогнозов.
- После противоречия отзывать модель затронутого действия и подтверждать
  новую версию свежими примерами, сохраняя остальные модели.
- Сохранять правила, версии и ограниченный набор источников в checkpoint;
  использовать их после запуска другого процесса без дообучения.

## Запуск

```bash
cargo run --locked --release --example learned_rules -- learn /tmp/aeterna-rules.json
cargo run --locked --release --example learned_rules -- run /tmp/aeterna-rules.json
```

В подготовленной облачной среде сначала выполните
`source /workspace/.aeterna-env/activate.sh`, если Cargo отсутствует в PATH.
Команда `learn` требует нового имени файла. `run` загружает модель, выключает
обучение и решает задачу с новым начальным наблюдением.

В библиотеке порядок включения такой:

1. Создать `EvoPhase` с числом каналов, действий и достаточным `dormant_cells`.
2. Включить `PhaseNativeConfig`, затем `PhaseOnlineConfig`.
3. До первого наблюдения вызвать `enable_phase_rule_learning(PhaseRuleConfig)`.
4. Использовать обычные `ScientificRuntime::observe_external`, `set_goal`
   и `step`/`step_unified` с внешними наблюдениями и результатами действия.

Готовый пример: [examples/learned_rules.rs](https://github.com/kelbas2007/Aeterna-v1/blob/research/beyond-intel4/examples/learned_rules.rs).
Правила мира находятся только во внешнем примере и не передаются организму.

## Реальный механизм

Базовый язык гипотез ограничен преобразованиями круговых каналов:

```text
post[j] = (orientation * pre[source] + acquired_offset) modulo 1
orientation ∈ {+1, -1}
```

Алгоритм и это семейство операций заданы разработчиком. Индекс источника,
ориентация и сдвиг приобретаются из опыта; цели и скрытые правила оценщика
не участвуют в приобретении. Один пример порождает кандидаты для всех
источников и обеих ориентаций. Последующие наблюдения исключают несовместимые
варианты. Подтверждение требует одного оставшегося кандидата для каждого
выхода и по умолчанию трёх различных PRE. Повторение того же PRE не увеличивает
число подтверждений. Этот порог — инженерный контракт, не универсальная
гарантия правильности произвольного правила.

Сдвиг хранится только в `PhaseSynapse::phase_offset` общих массивов носителя.
Прогноз читает этот параметр, вес и уверенность связи; отдельной запасной
копии сдвига в метаданных нет. Источники и ориентации хранятся в метаданных
кандидатов. Истинный результат действия остаётся внешним FACTUAL POST;
любой прогноз имеет `Authority::Imagined`, даже после подтверждения правила.

Выбор эксперимента сравнивает расхождение оставшихся прогнозов и дефицит
различных подтверждений. Если подтверждённое действие может переместить
организм в более информативную точку, допускается один такой шаг с последующим
перепланированием по реальному POST. Поиск пути к цели — явный программный
beam search над приобретёнными преобразованиями. Он имеет лимит глубины,
ширины и числа вычислений, не гарантирует нахождение всякого существующего
пути и не является приобретённым принципом исследования.

Таким образом, это **гибридный режим приобретённых правил с фазовыми
параметрами и программным поиском**. Он не квалифицирует полное EvoPhase
cognitive ownership и не заменяет прежний P1/P3 механизм. Режимы выбираются
явно; в режиме правил нет перехода к прежнему табличному вычислителю.

## Память и пересмотр

В базовом языке на старте резервируются `channels × actions` выходных ячеек и
`2 × channels² × actions` связей. По умолчанию на действие хранятся не более
восьми различных пар PRE/POST с монотонными идентификаторами источников.
Старое подтверждение вытесняется целиком; одинаковый PRE учитывается один раз
в текущем наборе оснований. Это ограниченная память, а не вся история жизни.

Противоречие означает, что хотя бы один выход фактического POST не согласуется
ни с одним оставшимся кандидатом. Отзывается вся текущая версия этого действия,
увеличивается revision и строятся новые кандидаты из настоящего POST.
До нового подтверждения правило не участвует в готовом плане. Правила других
действий сохраняются. Условные области применимости внутри одного действия
этот режим пока не учит.

Checkpoint v7 хранит приобретённые параметры и основания, исключая текущий
REAL, цель и actuator authority. Декодер проверяет размеры, адреса физических
связей, конфигурацию, уникальность источников и последовательность счётчиков.
Checkpoint v1–v5 остаются читаемыми. Проверка структуры
файла не удостоверяет его автора. Восстановление в живом runtime сохраняет
внешний emergency latch и требует нового наблюдения.

## Проверки

[tests/online_rules.rs](https://github.com/kelbas2007/Aeterna-v1/blob/research/beyond-intel4/tests/online_rules.rs) проверяет:

| Сценарий | Полученный результат |
| --- | --- |
| Cold acquisition в 32 мирах: 3–5 каналов, 2–4 непрозрачных действия, разные источники, отражения и сдвиги | Все модели приобретаются в пределах 80 действий на мир; суммарно 291 действие |
| Восстановление из файла, замороженная модель, новые начальные значения и цели из последовательностей до четырёх действий | 256/256 задач; начальные значения и цели отсутствуют в истории обучения, цель отличается от начального значения; learned fingerprint неизменен |
| Проверка прогнозов каждого действия независимым целочисленным вычислением оценщика | Прогнозы совпадают в допуске; их authority остаётся IMAGINED |
| Выбор между повторением известного PRE и действием, различающим варианты | Выбран различающий эксперимент; предложение само по себе не учит |
| Повторные PRE, изменение цели, блокировка и некорректный POST | Не создают дополнительного подтверждения |
| Изменение закона одного действия | Старая модель отозвана, новая подтверждается; другая модель сохраняется |
| Обнуление приобретённой связи, сдвиг её фазы на π, точное восстановление | Прогноз/план нарушаются; восстановление возвращает прежний результат |
| Повреждение checkpoint, старый формат, freeze и emergency restore | Повреждение отклоняется; старая модель и полномочия runtime сохраняются |
| Недостаточная глубина или бюджет поиска | Отказ от неподтверждённого плана; увеличение бюджета позволяет использовать то же приобретённое правило |

Это восемь development-тестов, созданных вместе с реализацией. 256 целей — восемь
задач для каждой из 32 приобретённых моделей, а не 256 независимых обучений.
Данные и бюджеты являются открытыми тестовыми fixtures; независимой научной
квалификации и преимущества над другими model-based алгоритмами не заявлено.

Обычная команда `bash scripts/check.sh` включает этот набор и предыдущие
регрессии. CI также запускает пример в двух отдельных процессах.

На этапе введения базовых правил общая регрессия завершилась с 89 успешными test invocations,
8 ignored и 79 filtered в 25 test binaries. Она включала исходные семь
тестов правил; после усиления held-out проверок и добавления отдельного
теста бюджета все восемь тестов правил повторно прошли в release.
Проверка компиляции всех целей также прошла. Счётчики разных test binaries
могут включать повторный запуск общих fixtures и не являются числом
независимых научных испытаний. Новая CI-конфигурация ещё не запускалась удалённо.
Clippy correctness прошёл; прежние предупреждения о стиле и неиспользуемом
коде сохранены.

Пример действительно запущен в двух отдельных процессах:

```text
mode=learn acquired_rules=2 acquisition_actions=6 heldout_goal=true goal_actions=4 stored_states=0 frozen_unchanged=true
mode=run acquired_rules=2 acquisition_actions=0 heldout_goal=true goal_actions=4 stored_states=0 frozen_unchanged=true
```

## Нерешённые ограничения

В базовом режиме каналы должны быть полностью наблюдаемыми, детерминированными и круговыми,
с каноническими значениями в `[0,1)`; `1.0` отклоняется. Воспринимаемый ноль
является значением, а не отсутствующим наблюдением. Погрешность декодирования
на границе круга канонизируется в пределах двух `f32::EPSILON`.

Поддерживаются до 16 каналов и 32 действий. Бюджеты планирования, физических
связей и свидетельств остаются явными. Режим не учит произвольные программы,
язык, зрительные инварианты, шум или условные законы.
При замороженной неподтверждённой модели либо отсутствии полного найденного
плана runtime возвращает `NoSupportedAction`. TE4 остаётся отрицательным
результатом. Общий интеллект этим расширением не создан.

Отдельное расширение [неполных наблюдений](PARTIAL_OBSERVATION.md) позволяет
применять приобретённые правила к скрытым каналам и выбирать действия для
получения недостающих измерений. Оно не обучает скрытым значениям по прогнозам:
для приобретения численного правила по-прежнему нужны фактические полные PRE/POST.
