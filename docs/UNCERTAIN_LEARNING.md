# Шумные частичные наблюдения и совместный обратный вывод

Этот седьмой opt-in режим находится в `research/beyond-intel4`. Он объединяет
приобретённые условные модели, шум измерений, частичные наблюдения и обратный
вывод в одном `ScientificRuntime`. Числовые параметры по-прежнему читаются из
физических фазовых связей; подбор формул и поиск плана выполняются программно.

## Что добавлено

- `PhaseInterval { center, radius }` задаёт круговой интервал; `None` означает
  весь круг. Интервалы могут пересекать ноль. Это инженерные границы при
  объявленных допущениях о модели и шуме, а не вероятности правильности ответа.
- Обратный вывод учитывает погрешности фактического POST, обученной модели и
  известных операндов. Коэффициенты ±2/±3 сохраняют все модульные корни.
- Два независимых уравнения с двумя общими операндами решаются совместно.
  Например, сумма и разность дают два решения на круге, а не одну выбранную
  точку. Зависимые уравнения оставляют непрерывную неопределённость.
- Приобретённое условие также проверяется по интервалу. Неизвестный контекст
  сохраняет несколько ветвей; неподтверждённый промежуток условия остаётся
  неизвестным. Центр интервала не выбирает ветвь за весь интервал.
- План должен довести **все** сохранённые альтернативы до видимой цели с
  учётом погрешности. При недостатке данных агент ищет полезное измерение.
  Среди измерений предпочитает приобретённое действие, сохраняющее каналы
  цели. Названия и роли моторов в API отсутствуют.
- Начальный ограниченный сбор опыта проверяет каждый мотор 32 раза по
  умолчанию. Воспроизводимое перемешивание равных приоритетов устраняет
  синхронизацию циклического порядка моторов с циклическим потоком примеров.
  Это заданная общая политика исследования, а не самостоятельно выученная
  универсальная стратегия любопытства.
- Уже измеренный канал не становится «новой информацией» из-за погрешности
  следующего воображаемого прогноза. Бесполезные измерения временно помечаются;
  нерелевантные скрытые каналы не требуют бесконечных повторных проб.

## Подключение и исполнение

На холодном организме сначала включите native/online planning, язык правил и
`enable_phase_adaptive_rules`. Затем вызовите
`enable_phase_uncertain_observation(PhasePartialConfig, PhaseUncertainConfig)`.
Нужны свободные клетки и связи для заранее ограниченного числа слотов моделей.
Можно также подключить новый режим к уже приобретённой полной adaptive-модели,
если обычный partial-режим ещё не включён.

Используйте `observe_external_partial`, `set_partial_goal` и `step_partial`.
Исполнитель возвращает только фактический `(Vec<Option<f32>>, outcome)`.
`phase_uncertain_belief()` и `phase_uncertain_predict()` возвращают интервальные
гипотезы с `Authority::Imagined`, источниками опыта и ревизией модели.
Старый exact partial API не выдаёт центры интервалов за точные значения.

**Числовое обучение требует фактических полных PRE и POST.** Восстановленные
центры не подставляются вместо пропущенного сенсора. Маски видимости учатся из
фактических частичных результатов. Это ограничение сохраняется и при
непрерывном пересмотре моделей: полностью скрытый закон с нуля ещё не обучается.

Цель считается достигнутой только по последнему фактическому измерению,
интервал которого целиком укладывается в допуск. Воображаемое попадание не даёт
REAL-успеха. Действия проходят существующий однократный permit и защитный шлюз.

## Ограничение памяти и работы

Настройки по умолчанию: радиус измерения 0.0005, 8192 операций одного вывода,
32 гипотезы, 64 примера на мотор, четыре слота модели. Радиус настраивается в
0–0.01, бюджет вывода в 128–1,000,000, квота исследования в 0–128 наблюдений
на мотор; ноль отключает начальную квоту.

При превышении числа гипотез они объединяются в покрывающие интервалы. При
исчерпании бюджета незавершённый вывод расширяется до неизвестного состояния.
Система теряет точность, сохраняя альтернативы. Поиск имеет отдельные границы
глубины, ширины и числа узлов. Это ограниченная память навыков, а не накопление
произвольных текстовых знаний на терабайты.

Checkpoint **v6** сохраняет конфигурацию, опыт и фазовые параметры. Он читает
старые v1–v5. Фактический текущий кадр, интервальные гипотезы, временные запреты
и разрешение исполнительного устройства не сохраняются. После восстановления
нужно новое наблюдение; заморозка обучения и аварийная остановка runtime
сохраняются при замене его знаний.

## Проверки и воспроизведение

```bash
cargo test --locked --release --test uncertain_learning --test iris_grounded -- --nocapture
cargo run --locked --release --example uncertain_learning -- learn /tmp/aeterna-uncertain.json
cargo run --locked --release --example uncertain_learning -- run /tmp/aeterna-uncertain.json
cargo run --locked --release --example iris_grounded
```

Используйте новый путь для `learn`: существующие знания не перезаписываются.
Пример после восстановления измеряет скрытый контекст и достигает фактической
цели за два действия с замороженной моделью.

Регрессии проверяют модульные корни и погрешность, независимый перебор 257²
внешних состояний, непрерывное множество при зависимых уравнениях, расширение
при лимитах, отсутствие обучения на предположениях, необходимость физических
связей/фазы, выбор измерения, отсутствие повторных бесполезных проб, атомарный
restore и одну жизнь A → B → A с частичными шумными результатами.
Отдельная [проверка Iris](IRIS_BENCHMARK.md) использует реальные записанные
измерения и сравнение с простым алгоритмом на тех же фактах.

Границы: известное ограниченное семейство круговых формул, один порог на модель,
фиксированные слоты, объявленная граница шума и full-tuple числовое обучение.
Допустимая доля выбросов adaptive-модели не означает гарантированного покрытия
каждого будущего наблюдения. Общий интеллект, понимание языка и холодное
стохастическое открытое обучение этим режимом не квалифицированы.
