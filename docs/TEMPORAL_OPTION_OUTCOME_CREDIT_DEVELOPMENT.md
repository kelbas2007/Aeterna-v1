# TEMPORAL-OPTION-OUTCOME-CREDIT — exposed engineering change

Date: 2026-10-20. AETERNA PR9 research-only; no new blind scientific verdict.

## Fault addressed

The first physical motor of a native U1-selected causal option could be an
invisible preparation. Previously its intrinsic novelty/real-time motor reward
trained U1 immediately, although the option's success depended on one or more
later protected physical actions. The subordinate motors correctly had no new
primitive-choice credit, but the original option was NEVER prospectively
credited for actually accomplishing its goal. This confounded exploration and
end-to-end trajectory value.

## Opt-in correction on the existing carrier, NOT a separate controller

- Applies only when the previously opt-in `enable_temporal_options` lane and
  a genuinely native-selected `predictive-suffix` route are active.
- The first expected physical action starts a bounded checkpoint-restorable
  eligibility trace. A verified preparation or continuation receives zero
  immediate U1 macro success credit.
- Every continuation still obtains a FRESH HumanProtection permit and must
  return its own REAL physical POST. No stage/role label, teacher schedule,
  fabricated success or counterfactual actuator access is introduced.
- ONLY a real reached goal delivers exactly one terminal U1 meta-utility update
  back to the original selected option fields. Authored bounded reward:
  `1 / (1 + 0.10 * ln(1 + total_real_external_cost))`.
  This discounts actual aggregate cost; it is not a self-invented utility law.
- An executed contradictory POST delivers a genuine zero outcome for the
  original choice, once. HumanProtection vetoes, external resets, unavailable
  motors and execution faults revoke/interrupt WITHOUT falsely blaming the
  cognitive policy for an unexecuted action.
- Option credit requires at least two feasible first-step motors. Physically
  forced identification experience continues to teach the factual model,
  but earns no fresh native decision credit.
- New persisted counters independently expose completed options, terminal
  outcome updates, actual contradicted outcomes and summed real success costs.
  Checkpoint validation checks bounds and source/sensor continuity.
