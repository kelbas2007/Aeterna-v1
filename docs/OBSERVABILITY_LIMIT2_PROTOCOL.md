Date 2026-10-20. Source-visible preregistration BEFORE any factor-two
evaluator code or result, parent `6819d16aa5f15d11be0f9bbfd7f742af1807b376`.

## Why this second test is needed
[OBSERVABILITY-LIMIT1](OBSERVABILITY_LIMIT1_RESULT.md) gave a strict
negative development result: exposing actual preparation stage in a
second sensor REGRESSED goals 487→194/864 and actual learned option
depth 3–5 completions 323→0. Simply adding true data is not sufficient.

A plausible cause: old autobiographical memory requires the entire
PRE/post vector to remain unchanged during latent prerequisites.
But `ScientificRuntime` already has an opt-in
`enable_constructing_certified_chains()`, a bounded BFS over REAL
PRE/action/POST-derived edges with prospective certificate and
HumanProtection on each chosen physical motor. It is currently
disabled in the cold sensor study. Test whether enabling that **existing
alternative route** repairs the observed mismatch without writing new
cognitive policy.

## Four-arm, matched source-disclosed factorial
All four arms start with exactly the same zero-experience native U1,
identical two sensor channels and policy, history options, complexity
need gate and contextual exploration, physical cost cap and goals.
Only two opt-ins vary:
- BLIND / NO CHAIN (existing limit1 control)
- TRUE STAGE / NO CHAIN (existing limit1 negative)
- BLIND / ENABLE CERTIFIED CHAIN
- TRUE STAGE / ENABLE CERTIFIED CHAIN

All actions are still native U1 decisions protected by
HumanProtection, and the supplied stage is an actual observed physical
value, NOT a fabricated POST or hidden-state inference. Training
action schedules, authored role labels and imagined fact injections
are forbidden.

Same 36 source-disclosed deterministic worlds and role maps: 12
four-action, 12 five-action, 6 three-action, 6 direct-goal control;
24 goal episodes/world, 18 real actions max per episode.
No new task/seed/role-map selection after observing outcomes.
Use existing hard-coded goal `[Some(1),None]`. Freeze negative
results as well as any positive signal.

## Admission criteria for meaningful sensor rescue
- In TRUE STAGE, chain ON must improve goals over chain OFF by
  at least **147 successes** across the 864 matched episodes (half the
  original 293-goal loss), and achieve **at least 100/144**
  on the old three-action family.
- Five-action TRUE STAGE chain ON must solve more than TRUE STAGE
  chain OFF and at least **4/288**, without regressing the direct-goal
  control.
- Total TRUE STAGE chain ON physical cost must be at most 110%
  of TRUE STAGE chain OFF, and real selected native chain actions
  (source `factual-chain`) must be >0. Merely proposing/considering
  a certificate is NOT success.
- Four original controls must keep real physical POST, cost, restart
  marks, zero tutor motor actions and valid checkpoint roundtrips.

If not all met, report `NO_CERTIFIED_CHAIN_SENSOR_RESCUE`
and preserve complete per-world/per-step traces.

This is a disclosed engineering *causal attribution* ablation,
not a fresh independent science exam, and does not demonstrate
self-generated sensors, active perception, autonomous new architecture
or AGI. If insufficient, advance to learning **goal-relevant
observation projections / state abstractions** from actual data
rather than adding more unrelated modules.
